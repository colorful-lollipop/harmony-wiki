# 安全风险评审

## 概述

本文档对 OpenHarmony 集成验证部件进行安全风险评审，分析项目的攻击面、信任边界和潜在风险。集成验证部件作为测试框架和工具集，其安全风险主要来源于执行环境、外部输入和工具集成等方面。

## 评审范围

### 代码范围

本次评审覆盖以下目录和文件：

- `cases/smoke/` - 门禁冒烟测试用例
- `cases/daily/` - 每日构建测试用例
- `tools/` - 工具集脚本
- `DeployDevice/` - 设备部署工具
- `cases/smoke/repo_cases_matrix.csv` - 用例配置文件

### 排除范围

根据项目约束，以下内容不在本次评审范围内：

- `test/` 目录下的自测试用例
- 第三方依赖库和开源工具
- CI/CD 平台本身的安全配置

## 已发现风险

### 风险 1：CSV 解析注入风险

**风险描述**：如果 `repo_cases_matrix.csv` 文件被恶意修改，可能导致 CSV 解析异常或注入攻击。

**证据来源**：`cases/smoke/repo_cases_matrix.csv`

```
| repository | bundle     | board1                | board2                | ...  |
| ---------- | ---------- | --------------------- | --------------------- | ---- |
| repo1      | component1 | test_case1            | test_case1;test_case2 | ...  |
```

**触发条件**：
1. CSV 文件包含恶意构造的内容
2. 文件在解析前未被验证

**潜在影响**：
- 解析错误导致测试失败
- 潜在的代码注入风险

**修复建议**：
1. 在解析 CSV 前进行内容验证
2. 对单元格内容进行转义处理
3. 限制可使用的字符范围

### 风险 2：命令行参数注入

**风险描述**：`tools/check.py` 等脚本在处理命令行参数时，如果参数未经严格校验，可能导致命令注入。

**证据来源**：`tools/check.py`

```python
# 潜在的风险模式（需要代码审查确认）
subprocess.run(args, shell=True)  # 如果使用 shell=True 则存在风险
```

**触发条件**：
1. 外部可控的参数传入脚本
2. 脚本使用 `shell=True` 执行命令

**潜在影响**：
- 任意代码执行
- 系统权限滥用

**修复建议**：
1. 避免使用 `shell=True`
2. 使用 `shlex.quote()` 转义参数
3. 使用参数列表而非字符串拼接

### 风险 3：用例文件路径遍历

**风险描述**：在用例选择和执行过程中，如果路径处理不当，可能导致路径遍历攻击。

**证据来源**：用例配置示例（README.md:42）

> 一般一个测试用例对应一个可执行文件，在门禁构建时产生和烧录设备。

**触发条件**：
1. 用例路径来自外部配置
2. 未对路径进行规范化处理

**潜在影响**：
- 读取/写入非授权目录
- 用例执行劫持

**修复建议**：
1. 使用 `os.path.abspath()` 规范化路径
2. 验证路径在预期目录内
3. 避免直接使用用户输入的路径

### 风险 4：设备通信安全

**风险描述**：`DeployDevice/` 目录下的工具在与物理设备通信时，可能存在通信安全问题。

**证据来源**：`DeployDevice/` 目录结构

**触发条件**：
1. 通过 USB 或网络与设备通信
2. 通信协议未加密或未认证

**潜在影响**：
- 设备伪装攻击
- 中间人攻击
- 固件篡改

**修复建议**：
1. 使用安全的通信协议
2. 对通信数据进行签名验证
3. 限制可部署的固件来源

### 风险 5：脚本执行环境隔离不足

**风险描述**：测试用例执行时，如果与宿主系统隔离不足，恶意用例可能影响宿主系统。

**触发条件**：
1. 用例以高权限执行
2. 未使用容器或沙箱隔离

**潜在影响**：
- 宿主系统被破坏
- 敏感数据泄露
- 横向移动攻击

**修复建议**：
1. 使用容器或沙箱执行测试
2. 限制用例执行的系统权限
3. 使用只读文件系统存储用例

## 安全最佳实践

### 开发阶段

| 实践 | 说明 |
|------|------|
| 输入验证 | 所有外部输入必须经过验证 |
| 最小权限 | 脚本使用最小必要权限执行 |
| 沙箱隔离 | 测试用例在隔离环境中执行 |
| 日志记录 | 记录所有安全相关的操作 |

### 部署阶段

| 实践 | 说明 |
|------|------|
| 访问控制 | 限制对配置文件的写权限 |
| 网络隔离 | 测试环境与生产环境隔离 |
| 固件签名 | 部署的固件必须经过签名验证 |

### 运维阶段

| 实践 | 说明 |
|------|------|
| 安全更新 | 定期更新依赖库和工具 |
| 日志审计 | 定期审查安全日志 |
| 渗透测试 | 定期进行安全测试 |

## 检查局限性说明

### 代码范围限制

本次评审基于以下假设和限制：

1. **未审查第三方代码**：仅审查项目自身的代码，不包含 Python 标准库和第三方依赖
2. **未进行动态测试**：评审基于静态代码分析，未进行实际执行测试
3. **CI/CD 平台**：未审查 CI/CD 平台的安全配置

### 技术限制

| 限制项 | 说明 |
|--------|------|
| 二进制分析 | 未对编译后的测试程序进行逆向分析 |
| 网络安全 | 未进行网络流量分析 |
| 硬件安全 | 未对设备固件进行安全分析 |

### 适用性说明

本评审适用于：
- 代码提交前的安全自查
- 安全审计的参考依据
- 安全改进的起点

本评审不适用于：
- 安全认证的完整评估
- 法律合规性证明
- 生产环境的安全验收

## 安全建议优先级

| 优先级 | 风险 | 建议 |
|--------|------|------|
| 高 | 命令注入风险 | 立即修复命令行参数处理 |
| 高 | 用例隔离不足 | 实施沙箱执行环境 |
| 中 | CSV 注入风险 | 增加输入验证 |
| 中 | 设备通信安全 | 实施通信加密和认证 |
| 低 | 路径遍历风险 | 增强路径处理逻辑 |

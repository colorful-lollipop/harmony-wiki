# 用例管理

## 概述

集成验证部件的测试用例分为两大类：门禁冒烟用例和每日构建用例。这两类用例在 CI/CD 流程中扮演不同的角色，服务于不同的质量保障目标。

## 用例分类

### 门禁冒烟用例

**位置**：`cases/smoke/`

**触发时机**：每次代码提交到代码仓库时自动触发

**执行频率**：高频，每次提交必执行

**执行时间**：通常 1-2 小时内完成

**主要特点**：
- 用例数量精简，覆盖核心功能
- 单个用例执行时间短
- 失败则阻止代码合入

**证据来源**：`README.md:4-5`

> 门禁冒烟对开发者的提交进行基本功能、部件功能和按场景的端到端测试

### 每日构建用例

**位置**：`cases/daily/`

**触发时机**：定时触发（每日多次）

**执行频率**：每日定时执行

**执行时间**：较长，视测试范围而定

**主要特点**：
- 用例覆盖面广，包含全量测试
- 进行版本归档
- 执行架构看护检查

**证据来源**：`README.md:6-7`

> 每日构建定时取 master 和 release 分支代码进行版本归档、全量 TDD 测试、最小系统测试和部件化的架构看护检查

│   │   └── [用例文件...]

│   │   └── [用例文件...]

## 用例配置管理

### repo_cases_matrix.csv 说明

门禁用例与代码仓库的关联关系通过 `cases/smoke/repo_cases_matrix.csv` 文件进行配置。

**文件位置**：`cases/smoke/repo_cases_matrix.csv`

**证据来源**：`README.md:35-41`

### 配置格式

| 列名 | 说明 | 示例 |
|------|------|------|
| repository | 仓库名称 | repo1 |
| bundle | 部件名称 | component1 |
| board1, board2, ... | 不同开发板的用例名称 | test_case1;test_case2 |

### 配置示例

```
| repository | bundle     | board1                | board2                | ...  |
| ---------- | ---------- | --------------------- | --------------------- | ---- |
| repo1      | component1 | test_case1            | test_case1;test_case2 | ...  |
| repo2      | component2 | test_case1;test_case2 | test_case1            | ...  |
```

**证据来源**：`README.md:37-41`

### 配置规则

1. **仓库关联**：每个仓库对应一行配置
2. **部件映射**：第二列标识该仓库所属的部件
3. **用例分配**：交集单元格填写针对该开发板的测试用例名称
4. **用例分隔**：多个用例使用分号（;）分隔

**证据来源**：`README.md:41-42`

> 一般一个测试用例对应一个可执行文件，在门禁构建时产生和烧录设备。

### 新增用例步骤

当需要为某个仓库新增门禁用例时，操作流程如下：

1. **确定仓库**：在 CSV 文件中找到对应的仓库行（第一列）
2. **选择开发板**：确定需要添加用例的开发板列
3. **编写用例**：按照该模块的用例规范编写测试代码
4. **配置关联**：在对应单元格中添加用例名称
5. **提交验证**：提交更改并等待门禁验证结果

### 用例命名规范

| 用例类型 | 命名模式 | 示例 |
|----------|----------|------|
| 音频用例 | audio_[功能名] | audio_playback |
| 基础用例 | basic_[功能名] | basic_startup |
| 截图用例 | screenshot_[尺寸] | screenshot_1920x1080 |
| 分布式用例 | distributed_[场景] | distributed_file_sync |
| 视频用例 | video_[功能名] | video_decode |

## 用例执行模型

### 门禁执行流程

```
[代码提交] --> [门禁触发] --> [用例选择] --> [用例编译] --> [设备烧录] --> [用例执行] --> [结果收集] --> [报告生成]
```

### 每日构建执行流程

```
[定时触发] --> [代码拉取] --> [版本归档] --> [用例编译] --> [TDD测试] --> [最小系统测试] --> [架构检查] --> [报告归档]
```

## 用例与开发板的对应关系

### 开发板支持矩阵

| 用例目录 | 支持的开发板 | 说明 |
|----------|--------------|------|
| screenshot32 | 32位开发板 | 32位系统的截图功能测试 |
| screenshot64 | 64位开发板 | 64位系统的截图功能测试 |
| audio | 所有标准开发板 | 音频功能测试 |
| video | 支持视频编解码的开发板 | 视频功能测试 |
| distributed | 支持分布式能力的开发板 | 分布式场景测试 |
| mini_system | 标准开发板 | 最小系统功能验证 |

### 开发板配置

开发板的配置信息通常在 `repo_cases_matrix.csv` 的表头行中定义。不同的开发板可能具有不同的硬件能力和系统配置。

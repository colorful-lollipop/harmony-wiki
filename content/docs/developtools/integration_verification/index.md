# 集成验证部件概览

## 项目定位

集成验证部件是 OpenHarmony 开发工具链中的质量保障组件，负责对整个 OpenHarmony 系统进行集成测试和验证。该部件位于代码仓库的 `developtools/integration_verification` 目录下，是 OpenHarmony CI/CD 流程中的关键环节。

**证据来源**：`README.md:1-6`

> 集成验证包含门禁冒烟和每日构建两个功能：
> - 门禁冒烟对开发者的提交进行基本功能、部件功能和按场景的端到端测试；
> - 每日构建定时取 master 和 release 分支代码进行版本归档、全量 TDD 测试、最小系统测试和部件化的架构看护检查。

## 核心能力

### 门禁冒烟测试

门禁冒烟（Smoke Testing）是 CI 流程的第一道关卡，负责对开发者的每次代码提交进行快速验证。其核心能力包括：

1. **基本功能测试**：验证系统的核心功能是否正常
2. **部件功能测试**：针对各子系统进行功能验证
3. **端到端场景测试**：按照特定业务场景进行完整流程测试

**证据来源**：`README.md:4-5`

### 每日构建

每日构建（Daily Build）是定时触发的全面验证流程，确保系统每日构建的稳定性。其核心能力包括：

1. **版本归档**：保存每日构建的版本快照
2. **全量 TDD 测试**：执行完整的测试用例集
3. **最小系统测试**：验证最小系统配置下的功能完整性
4. **架构看护检查**：检查系统架构的合规性

**证据来源**：`README.md:6-7`

## 关键概念

### 门禁

门禁是 OpenHarmony CI 流程中的一个质量关卡，所有代码提交必须通过门禁测试才能合入主干。门禁测试的特点是：

- **触发时机**：每次代码提交时自动触发
- **执行时间**：通常在 1-2 小时内完成
- **覆盖面**：聚焦于核心功能和关键场景
- **失败策略**：门禁失败会阻止代码合入

### 冒烟用例

冒烟用例是门禁测试中使用的测试用例集合，具有以下特点：

- **数量精简**：通常选取最具代表性的测试用例
- **执行快速**：单个用例执行时间控制在合理范围内
- **结果明确**：通过/失败有明确的判定标准

**证据来源**：`README.md:32-42`

### 制品库配置

门禁用例与代码仓库的关联关系通过 `cases/smoke/repo_cases_matrix.csv` 文件配置。

**证据来源**：`README.md:35-41`

| 列名 | 说明 |
|------|------|
| 第一列（repository） | 仓库名称 |
| 第二列（bundle） | 部件名称 |
| 第三列及以后 | 不同开发板的用例名称 |

## 快速入门

### 新增门禁用例

当新建仓库或仓库对应系统功能发生变化时，需要在门禁中添加冒烟用例关联。操作步骤如下：

1. 打开 `cases/smoke/repo_cases_matrix.csv` 文件
2. 在对应仓库行添加新的用例名称
3. 提交更改并等待门禁验证

### 运行本地测试

1. 确保开发环境已配置完成
2. 根据测试类型选择对应的用例目录
3. 执行相应的测试脚本

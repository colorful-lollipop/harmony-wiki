## 1. 目的与范围

本文档对 `restool`（OpenHarmony 资源编译工具）进行**安全风险评审**，提供：
- 威胁模型概述
- 详细风险分析（含利用路径）
- 修复建议
- 安全使用指南

**评审范围**: `src/` 和 `include/` 目录下的源代码（不包括测试代码）

**核心发现**：
- 🔴 **高危风险**: 2 个（路径遍历、动态库劫持）
- 🟡 **中危风险**: 3 个（JSON DoS、ReDoS、资源耗尽）
- 🟢 **低危风险**: 2 个（信息泄露、竞态条件）

### 总体安全评估

**restool** 是一个**纯命令行编译工具**，安全特性如下：

| 特性 | 状态 | 说明 |
|------|------|------|
| **网络通信** | ✅ 无 | 不涉及网络攻击面 |
| **IPC/SA 接口** | ✅ 无 | 不涉及进程间通信攻击 |
| **权限提升** | ✅ 无 | 以调用者权限运行 |
| **文件系统操作** | ⚠️ 有风险 | 存在路径遍历风险（[RESTOOL-SEC-001](#41-路径遍历攻击)） |
| **动态库加载** | ⚠️ 有风险 | 存在 DLL/SO 劫持风险（[RESTOOL-SEC-002](#42-动态库加载劫持)） |

## 4. 详细风险分析

> **说明**: 攻击面详情请参阅 [05_AttackSurface.md](05_AttackSurface.md)，本文档重点分析**漏洞利用方式**和**修复建议**。

### 4.1 🔴 高危风险 1：路径遍历攻击

| 属性 | 值 |
|------|-----|
| **风险 ID** | RESTOOL-SEC-001 |
| **风险等级** | 🔴 高危 |
| **利用难度** | ⭐⭐⭐ 低（可直接利用） |
| **影响范围** | 文件系统任意位置 |
| **触发模块** | `FileEntry`、`PackageParser` |

#### 4.1.1 代码证据

**位置**: `src/file_entry.cpp`

| 行号 | 代码 | 操作类型 |
|------|------|---------|
| 314 | `remove(path.c_str())` | 删除文件 |
| 331 | `rmdir(path.c_str())` | 删除目录 |
| 347 | `mkdir(path.c_str(), ...)` | 创建目录 |
| 168-169 | `ifstream/ofstream` | 文件复制 |
| 304-338 | `RemoveAllDirInner()` | 递归删除 |

#### 4.1.2 调用链（输入 → 漏洞点）

```
用户输入 (-i/-o/-r 参数)
    ↓ src/cmd/cmd_parser.cpp:39 CmdParser::Parse()
PackageParser::AddInput() / AddOutput() / AddResourceHeader()
    ↓ src/cmd/package_parser.cpp
FileEntry::CreateDirs() / RemoveAllDir() / RemoveFile()
    ↓ src/file_entry.cpp:314/331/347
mkdir() / rmdir() / remove() 系统调用
```

#### 4.1.3 利用场景

```bash
# 场景 1：通过相对路径遍历删除任意目录
restool -i "./resources/../../../etc"

# 场景 2：覆盖系统文件
restool -i "./resources" -o "../../../etc/passwd"

# 场景 3：配合 -f 强制覆盖选项
restool -i "./resources" -o "/etc/passwd" -f
```

#### 4.1.4 影响评估

| 影响项 | 评估 |
|--------|------|
| **权限提升** | 无（以当前用户权限执行） |
| **数据完整性** | 可删除/覆盖任意文件 |
| **可用性** | 可导致系统关键文件丢失 |
| **可利用性** | 高（直接命令行利用） |

#### 4.1.5 修复建议

| 优先级 | 建议 | 实现难度 |
|--------|------|---------|
| **P0** | 路径规范化：使用 `realpath()` 解析绝对路径 | 中 |
| **P0** | 基目录检查：验证路径是否在允许范围内 | 低 |
| **P1** | 禁止相对路径穿越：拒绝包含 `..` 的路径组件 | 低 |
| **P2** | 权限检查：创建/删除前验证权限 | 低 |

**代码示例**：
```cpp
// 建议实现的安全路径检查
bool IsPathSafe(const string& path, const string& basePath) {
    char resolvedPath[PATH_MAX];
    if (!realpath(path.c_str(), resolvedPath)) {
        return false;  // 路径无效
    }
    string resolved(resolvedPath);
    // 检查是否在基目录内
    return resolved.find(basePath) == 0 && 
           resolved.size() > basePath.size() &&
           resolved[basePath.size()] == '/';
}
```

### 4.2 🔴 高危风险 2：动态库加载劫持

| 属性 | 值 |
|------|-----|
| **风险 ID** | RESTOOL-SEC-002 |
| **风险等级** | 🔴 高危 |
| **利用难度** | ⭐⭐ 中（需构造配置文件） |
| **影响范围** | 完整代码执行 |
| **触发模块** | `CompressionParser` |

#### 4.2.1 代码证据

**位置**: `src/compression_parser.cpp`

| 行号 | 代码 | 操作 |
|------|------|------|
| 61-69 | `dlclose()` / `FreeLibrary()` | 卸载动态库 |
| 89-122 | `cJSON_Parse()` | 解析配置文件 |
| 103 | `LoadImageTranscoder()` | 加载动态库 |

```cpp
// src/compression_parser.cpp:61-69
#ifdef __WIN32
    if (handle_) {
        FreeLibrary(handle_);
        handle_ = nullptr;
    }
#else
    if (handle_) {
        dlclose(handle_);
        handle_ = nullptr;
    }
#endif
```

#### 4.2.2 调用链（输入 → 漏洞点）

```
--compressed-config 参数指定配置文件
    ↓ src/compression_parser.cpp:89
CompressionParser::Init()
    ↓
ParseContext() 读取 extensionPath
    ↓ src/compression_parser.cpp:103
LoadImageTranscoder()
    ↓
dlopen() / LoadLibrary() 加载指定路径的动态库
```

#### 4.2.3 利用场景

```json
// 恶意 opt-compression.json
{
    "context": {
        "extensionPath": "./malicious_lib.so"
    },
    "compression": {
        "media": { "enable": true }
    }
}
```

```bash
# 执行攻击
restool -i ./resources --compressed-config ./malicious.json ...
```

**攻击效果**：加载任意路径的恶意 SO/DLL 文件，执行任意代码。

#### 4.2.4 影响评估

| 影响项 | 评估 |
|--------|------|
| **权限提升** | 可获取 restool 进程权限 |
| **代码执行** | ✅ 可执行任意代码 |
| **数据窃取** | ✅ 可读取任意文件 |
| **横向移动** | ✅ 可攻击构建系统 |

#### 4.2.5 修复建议

| 优先级 | 建议 | 实现难度 |
|--------|------|---------|
| **P0** | 库路径白名单：只允许加载 SDK 目录下的库 | 低 |
| **P0** | 禁止相对路径：拒绝 `./`、`../` 开头的路径 | 低 |
| **P1** | 签名验证：验证动态库的数字签名 | 中 |
| **P2** | 权限降级：以低权限加载不可信库 | 中 |

## 6. 安全使用建议

### 6.1 对使用者

| 建议 | 说明 |
|------|------|
| ❌ **不要以 root 权限运行** | 限制攻击影响范围 |
| ✅ **验证所有输入路径** | 防止路径遍历 |
| ✅ **不要加载不可信压缩配置** | 防止动态库劫持 |
| ✅ **限制线程数在合理范围** | 防止资源耗尽 |
| ✅ **在隔离环境中运行** | 如容器或沙箱 |

### 6.2 对集成者

| 建议 | 说明 |
|------|------|
| ✅ **参数校验** | 调用前验证所有参数 |
| ✅ **路径白名单** | 只允许特定目录 |
| ✅ **沙箱执行** | 限制文件访问 |
| ✅ **权限最小化** | 使用最小权限运行 |
| ✅ **异常监控** | 监控异常行为 |

### 6.3 CI/CD 集成建议

```yaml
# GitHub Actions 示例
- name: Run restool
  run: |
    # 限制线程数
    restool -i ./resources --thread 8 ...
    # 白名单路径
    -o ./build/output
```

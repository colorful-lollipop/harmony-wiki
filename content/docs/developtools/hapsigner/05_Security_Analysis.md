# 安全风险分析

## 目的

本文档基于代码证据对 hapsigner 进行安全风险评审，识别攻击面、信任边界和可被利用点，并提供修复建议。

## 适用范围

- 安全审计人员
- 代码审查人员
- 安全开发人员

---

## 检查范围

| 模块 | 检查内容 | 代码路径 |
|------|----------|----------|
| 命令处理 | 参数解析、密码输入 | `cmd/src/params_run_tool.cpp` |
| 文件操作 | 文件读写、路径处理 | `utils/src/file_utils.cpp` |
| 内存操作 | 缓冲区管理、内存拷贝 | `common/src/byte_buffer.cpp` |
| 密码学操作 | 密钥管理、签名验证 | `utils/src/key_store_helper.cpp` |
| 代码签名 | Merkle树、FsVerity | `codesigning/` |

### 1. 命令行接口攻击面

| 攻击面 | 风险等级 | 说明 |
|--------|----------|------|
| 参数注入 | 中 | 命令行参数解析可能存在注入风险 |
| 密码泄露 | 高 | 密码可能通过命令历史泄露 |
| 文件路径遍历 | 中 | 输入文件路径未严格校验 |

### 2. 文件操作攻击面

| 攻击面 | 风险等级 | 说明 |
|--------|----------|------|
| 路径遍历 | 中 | 输出文件路径可能包含 `../` |
| 临时文件 | 低 | 签名过程中创建临时文件 |
| 文件权限 | 中 | 输出文件权限设置不当 |

### 3. 密码学操作攻击面

| 攻击面 | 风险等级 | 说明 |
|--------|----------|------|
| 密钥存储 | 高 | Keystore 文件权限和加密强度 |

| 攻击面 | 风险等级 | 说明 |
|--------|----------|------|
| 缓冲区溢出 | 中 | C++ 代码中的缓冲区操作 |
| 内存泄漏 | 低 | 动态内存分配未释放 |
| 整数溢出 | 中 | 大小计算可能溢出 |

## 可被利用点分析

### 风险 1: 密码内存未及时清零

**证据**: `hapsigntool_cpp/api/src/sign_tool_service_impl.cpp:381,426`

```cpp
adapter->ResetPwd(); // clean pwd for safety
```

**分析**:
- 密码在内存中存储，虽然有 `ResetPwd()` 清理，但清理时机和彻底性需要验证
- Java 版本依赖 JVM 垃圾回收，密码可能在内存中残留较长时间

**影响**: 中 - 攻击者可能通过内存转储获取密码

**修复建议**:
1. 使用专用安全内存分配器（如 `secure_malloc`）
2. 确保密码使用后立即清零
3. 考虑使用内存锁定防止交换到磁盘

---

### 风险 2: 文件路径遍历

**证据**: `hapsigntool_cpp/utils/src/file_utils.cpp`

```cpp
int FileUtils::Write(const std::string& content, const std::string& output) {
    std::ofstream outFile(output, std::ios::binary);
    // 未对 output 路径进行遍历检查
}
```

**分析**:
- 输出文件路径直接来自用户输入，未进行路径规范化
- 可能通过 `../` 写入系统敏感位置

**影响**: 中 - 可能导致文件覆盖或信息泄露

**修复建议**:
1. 对输出路径进行规范化处理（使用 `realpath` 或 `std::filesystem::canonical`）
2. 检查路径是否在允许的工作目录内
3. 拒绝包含 `..` 的路径组件

---

### 风险 3: 整数溢出导致缓冲区问题

**证据**: `hapsigntool_cpp/hap/sign/src/sign_elf.cpp:284-289`

```cpp
bool SignElf::IsLongOverflowInteger(const int64_t num) {
    return num > INT_MAX || num < INT_MIN;
}
```

**分析**:
- 代码中有对整数溢出的检查，但检查点分散
- 某些边界情况可能未覆盖

**影响**: 中 - 可能导致缓冲区溢出或逻辑错误

**修复建议**:
1. 统一使用安全整数运算库
2. 在大小计算处添加溢出检查
3. 使用 `size_t` 等无符号类型时注意下溢

---

### 风险 4: 缓冲区操作安全

**证据**: `hapsigntool_cpp/common/src/byte_buffer.cpp`

```cpp
void ByteBuffer::PutData(int32_t offset, const char data[], int32_t len) {
    if (buffer != nullptr && data != nullptr && offset >= 0 && len > 0 && (limit - offset) >= len) {
        if (memcpy_s((buffer.get() + offset), (limit - offset), data, len) != EOK) {
            SIGNATURE_TOOLS_LOGE("memcpy_s failed");
        }
    }
}
```

**分析**:
- 使用了 `memcpy_s` 等安全函数
- 但错误处理仅记录日志，未阻止后续操作
- 某些边界条件检查可能不完整

**影响**: 低-中 - 可能导致数据损坏或信息泄露

**修复建议**:
1. 缓冲区操作失败时立即返回错误
2. 添加更严格的边界检查
3. 使用智能指针管理缓冲区生命周期

---

### 风险 5: 密码输入超时机制

**证据**: `hapsigntool_cpp/common/include/password_guard.h:34`

```cpp
bool readPasswordWithTimeout(const std::string &prompt = "Enter password: ");
```

**分析**:
- 密码输入有超时机制（30秒），但实现依赖 `poll()`
- 超时后密码可能残留在终端缓冲区

**影响**: 低 - 可能导致密码泄露

**修复建议**:
1. 确保超时后清理输入缓冲区
2. 使用更安全的终端输入方式
3. 考虑使用密钥文件代替交互式密码输入

---

### 风险 6: ZIP 文件解析安全

**证据**: `hapsigntool_cpp/codesigning/sign/src/code_signing.cpp:288-300`

```cpp
char szReadBuffer[BUFFER_SIZE] = { 0 };
if (memset_s(szReadBuffer, BUFFER_SIZE, 0, BUFFER_SIZE) != EOK) {
    // error handling
}
nReadFileSize = unzReadCurrentFile(zFile, szReadBuffer, BUFFER_SIZE);
sb.sputn(szReadBuffer, nReadFileSize);
```

**分析**:
- ZIP 文件解析依赖第三方库（minizip）
- 恶意构造的 ZIP 文件可能导致解析问题

**影响**: 中 - 可能导致拒绝服务或代码执行

**修复建议**:
1. 对 ZIP 文件进行格式验证
2. 限制解压文件大小和数量
3. 在沙箱环境中解析不可信 ZIP 文件

---

### 风险 7: 证书验证绕过

**证据**: `hapsigntool_cpp/api/src/sign_tool_service_impl.cpp:92-94`

```cpp
if (!X509CertVerify(certPtr, rootKey)) {
    SIGNATURE_TOOLS_LOGE("generate root cert failed because verify failed!");
    break;
}
```

**分析**:
- 证书验证逻辑存在，但验证强度需要确认
- 可能接受弱签名算法或过期证书

**影响**: 高 - 可能导致接受伪造证书

**修复建议**:
1. 强制使用强签名算法（SHA256 及以上）
2. 验证证书有效期和吊销状态
3. 检查证书链完整性

---

### 风险 8: 代码签名数据篡改

**证据**: `hapsigntool_cpp/codesigning/fsverity/src/merkle_tree_builder.cpp`

**分析**:
- Merkle 树构建过程中数据完整性依赖输入流
- 并发修改可能导致不一致

**影响**: 中 - 可能导致代码签名验证绕过

**修复建议**:
1. 对输入文件进行锁定防止并发修改
2. 计算哈希前验证文件完整性
3. 使用原子操作写入签名数据

---

### 风险 9: 日志信息泄露

**分析**:
- 日志可能包含敏感信息（文件路径、错误详情）
- 调试日志可能在生产环境启用

**影响**: 低 - 可能泄露系统信息

**修复建议**:
1. 日志中避免记录敏感信息
2. 区分调试日志和生产日志级别
3. 定期清理日志文件

---

### 风险 10: 依赖库安全

**分析**:
- 项目依赖 OpenSSL、BouncyCastle 等加密库
- 依赖库版本可能存在已知漏洞

**影响**: 中 - 可能受依赖库漏洞影响

**修复建议**:
1. 定期更新依赖库到最新版本
2. 监控依赖库安全公告
3. 使用静态分析工具扫描依赖

## 局限性说明

1. **静态分析限制**: 本文档基于静态代码分析，未进行动态测试
2. **依赖库深度**: 未深入分析第三方依赖库的实现细节
3. **测试覆盖**: 未验证所有代码路径的安全性问题
4. **环境假设**: 分析基于标准运行环境，特殊环境可能有额外风险

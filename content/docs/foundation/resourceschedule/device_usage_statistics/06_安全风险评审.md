# 安全风险评审

## 目的

本文档提供 device_usage_statistics 组件的安全风险分析，包括攻击面、信任边界、潜在可被利用点和修复建议。

## 适用范围

- 权限检查机制
- 输入校验和防护
- 数据库操作安全
- IPC 通信安全
- 内存安全管理

---

## 攻击面分析

### 1. N-API 接口攻击面

**攻击向量**:
- 恶意 JS 应用调用 N-API 接口
- 传入畸形参数或超长字符串
- 伪造 bundleName 或时间戳

**暴露接口**:
- `setAppGroup()` - 需要系统权限和 BUNDLE_ACTIVE_INFO 权限
- `registerAppGroupCallBack()` - 注册分组变更回调
- 所有查询接口 - 无权限要求

**防护措施**:
- 权限检查：`VerifyAccessToken()` 验证 BUNDLE_ACTIVE_INFO 权限
- 系统应用检查：`IsSystemAppByFullTokenID()` 验证调用者
- 参数校验：类型检查、范围检查、空值检查

**证据**:
- services/common/src/bundle_active_service.cpp:717-766: 权限检查实现
- frameworks/src/bundle_state_query_napi.cpp: 参数解析函数

---

### 2. IPC 通信攻击面

**攻击向量**:
- 恶意应用通过 IPC 直接调用 System Ability
- 伪造 Token ID 或 UID
- IPC 数据注入

**暴露接口**:
- SA 1907 (DEVICE_USAGE_STATISTICS_SYS_ABILITY_ID)
- 所有 IBundleActiveService 接口方法

**防护措施**:
- IPC 框架保护：Binder 安全机制
- 调用者信息验证：`GetCallingTokenID()`, `GetCallingUid()`
- 权限检查：所有敏感操作需要权限验证

**证据**:
- services/common/src/bundle_active_service.cpp:256-264: 调用者信息获取
- sa_profile/1907.json: SA 配置

---

### 3. 数据库操作攻击面

**攻击向量**:
- SQL 注入
- 路径遍历
- 数据库文件篡改

**防护措施**:
- 参数化查询：使用 selectionArgs 替代字符串拼接
- RDB 安全级别：S1 安全级别
- WAL 模式：Write-Ahead Logging 保证一致性
- 固定数据库路径：使用常量定义路径

**证据**:
- services/common/src/bundle_active_usage_database.cpp:223: QueryByStep 使用参数化查询
- services/common/src/bundle_active_config_reader.cpp:186-199: 路径规范化

**防护措施**:

**证据**:

**攻击向量**:

## 信任边界

### 1. N-API 层 → IPC 层

**边界**:
- N-API 层在 JS 线程执行
- IPC 调用通过 Binder 传输到服务进程

**信任假设**:
- JS 应用可能是恶意的
- 所有外部输入都需校验
- 不信任任何来自 JS 的数据

**证据**:
- frameworks/src/bundle_state_query_napi.cpp: 参数校验函数

---

### 2. IPC 客户端 → IPC 服务端

**边界**:
- IPC 客户端在应用进程
- IPC 服务端在 `resource_schedule_service` 系统进程

**信任假设**:
- 不信任任何 IPC 调用者
- 必须验证调用者身份（Token ID, UID）
- 所有敏感操作需要额外权限检查

**证据**:
- services/common/src/bundle_active_service.cpp:717-766: 权限检查函数

---

### 3. 服务层 → 数据库层

**边界**:
- 服务层在系统进程
- 数据库文件在 `/data/service/el2/database/bundle_active/`

**信任假设**:
- 数据库操作需使用参数化查询
- 避免直接拼接 SQL
- 验证所有输入数据

**证据**:
- services/common/src/bundle_active_usage_database.cpp: 数据库操作实现

## 潜在可被利用点（8个）

### 风险 1: SQL 注入风险 - 表名动态拼接

**位置**: `services/common/src/bundle_active_usage_database.cpp:350-352, 409-411, 417-419`

**风险等级**: 中

**代码片段**:
```cpp
string deleteEventDataSql = "delete from " + eventTableName_ + " where timeStamp <= " + to_string(deleteTimePoint);
int32_t deleteResult = rdbStore->ExecuteSql(deleteEventDataSql);
```

**触发条件**:
- 恶意应用通过正常途径无法直接触发
- 风险主要在于代码维护时可能引入问题

**影响**:
- 如果 `deleteTimePoint` 构造不当，可能执行非预期的 SQL

**修复建议**:
- 使用参数化查询，避免直接拼接 SQL
- 对 `eventTableName_` 进行白名单验证
- 添加输入数据范围检查

**证据**:
- services/common/src/bundle_active_usage_database.cpp:350-352: SQL 拼接代码

---

### 风险 2: 路径遍历风险 - 配置文件加载

**位置**: `services/common/src/bundle_active_config_reader.cpp:160-182`

**风险等级**: 低

**代码片段**:
```cpp
bool BundleActiveConfigReader::ConvertFullPath(const std::string& partialPath, std::string& fullPath) {
    if (partialPath.empty() || partialPath.length() >= PATH_MAX) {
        return false;
    }
    char tmpPath[PATH_MAX] = {0};
    if (realpath(partialPath.c_str(), tmpPath) == nullptr) {
        return false;
    }
    fullPath = tmpPath;
    return true;
}
```

**触发条件**:
- 配置文件路径由外部配置提供
- 虽有 `realpath()` 保护，但需确保 PATH_MAX 检查有效

**影响**:
- 如果 `realpath()` 失败或返回值处理不当，可能读取非预期文件

**修复建议**:
- 确认 `realpath()` 返回值处理正确
- 添加额外的路径合法性检查
- 记录失败的路径加载尝试

**证据**:
- services/common/src/bundle_active_config_reader.cpp:160-182: 路径规范化代码

### 风险 3: 整数溢出风险 - 时间戳处理

**位置**: `services/common/src/bundle_active_usage_database.cpp:429-446`

**风险等级**: 低

**代码片段**:
```cpp
int64_t BundleActiveUsageDatabase::ParseStartTime(const string &tableName) {
    // ...
    for (uint32_t i = 0; i < tableTime.length(); i++) {
        if (tableTime[i] >= '0' && tableTime[i] <= '9') {
            tableTime = tableTime.substr(i);
            break;
        }
    }
    return atoll(tableTime.c_str());  // 潜在溢出风险
}
```

**触发条件**:
- `atoll()` 对异常输入可能产生未定义行为

**影响**:
- 错误的时间戳可能导致查询结果错误

**修复建议**:
- 使用 `strtoll()` 替代 `atoll()`
- 检查 `errno` 判断转换是否成功
- 添加范围检查

**证据**:
- services/common/src/bundle_active_usage_database.cpp:429-446: 时间戳解析代码

### 风险 4: IPC 输入未充分校验 - Dump 接口

**位置**: `services/common/src/bundle_active_service.cpp:910-1007`

**风险等级**: 中

**代码片段**:
```cpp
int32_t BundleActiveService::Dump(int32_t fd, const std::vector<std::u16string> &args) {
    // ...
    int64_t beginTime = BundleActiveUtil::StringToInt64(dumpOption[2]);
    int64_t endTime = BundleActiveUtil::StringToInt64(dumpOption[3]);
    int32_t userId = BundleActiveUtil::StringToInt32(dumpOption[4]);
```

**触发条件**:

- 虽有 `AllowDump()` 权限检查，但参数校验需加强

**影响**:
- 溢出的整数值可能导致未定义行为

**修复建议**:
- 加强 `StringToInt64()` 和 `StringToInt32()` 的溢出检查
- 添加参数数量和范围验证
- 记录非法的 Dump 调用

**证据**:
- services/common/src/bundle_active_service.cpp:910-1007: Dump 接口实现

### 风险 5: 空指针解引用风险 - bundleActiveCore_

**位置**: `services/common/src/bundle_active_service.cpp:950-952`

**风险等级**: 低

**代码片段**:
```cpp
int32_t BundleActiveService::ShellDump(const std::vector<std::string> &dumpOption, std::vector<std::string> &dumpInfo) {
    int32_t ret = -1;
    if (!bundleActiveCore_) {
        return ret;
    }
```

**触发条件**:
- 多线程环境下存在 race condition
- 虽然 `bundleActiveCore_` 有检查，但在检查和使用之间可能被修改

**影响**:
- 空指针解引用导致崩溃

**修复建议**:
- 使用 `std::shared_ptr` 或添加锁保护
- 或使用原子指针

**证据**:
- services/common/src/bundle_active_service.cpp:950-952: 空指针检查

### 风险 6: bundleName 字符串操作未校验长度

**位置**: `services/packagegroup/src/bundle_active_group_controller.cpp:366-368`

**风险等级**: 低

**代码片段**:

```cpp
for (auto packageHistoryIter : *packageHistoryMap) {
```

**触发条件**:

**影响**:
- 性能问题或潜在的 DoS 攻击

**修复建议**:
- 添加 bundleName 长度限制（如 256 字符）
- 使用白名单校验 bundleName 格式

**证据**:
- services/packagegroup/src/bundle_active_group_controller.cpp:366-368: bundleName 使用

### 风险 7: 内存泄漏风险 - cJSON 未释放

**位置**: `services/common/src/bundle_active_config_reader.cpp:84-94`

**风险等级**: 低

**代码片段**:
```cpp
cJSON *root = nullptr;
if (!GetJsonFromFile(filePath, root) || !root) {
    BUNDLE_ACTIVE_LOGE("file is empty %{private}s", filePath);
    return;
}
// LCOV_EXCL_START
LoadApplicationUsePeriodically(root);
// ...
cJSON_Delete(root);  // 正常路径会释放
```

**触发条件**:
- 异常路径 `return` 时未释放 `root`
- 但 `root` 为 nullptr 时无需释放

**影响**:
- 内存泄漏积累导致系统资源耗尽

**修复建议**:
- 使用 RAII 模式管理 cJSON 资源
- 确认所有异常路径的内存处理

**证据**:
- services/common/src/bundle_active_config_reader.cpp:84-94: cJSON 使用

### 风险 8: 并发访问风险 - userStatServices_ 无锁访问

**位置**: `services/common/src/bundle_active_core.cpp:390-411`

**风险等级**: 中

**代码片段**:
```cpp
void BundleActiveCore::RestoreAllData() {
```

**修复建议**:

- 或使用读写锁（std::shared_mutex）

**证据**:

## 安全建议

### 优先级高

1. **SQL 注入防护**
   - 使用参数化查询替代字符串拼接
   - 对动态表名进行白名单验证
   - 添加输入数据范围检查

2. **Dump 接口参数校验**
   - 加强数值转换函数的溢出检查
   - 添加参数数量和范围验证
   - 记录非法的 Dump 调用

3. **并发安全**
   - 为共享数据结构添加锁保护
   - 使用读写锁优化性能

---

### 优先级中

4. **路径遍历防护增强**
   - 确认 `realpath()` 返回值处理正确
   - 添加额外的路径合法性检查

5. **整数溢出防护**
   - 使用 `strtoll()` 替代 `atoll()`
   - 检查 `errno` 判断转换是否成功

6. **内存管理**
   - 使用 RAII 模式管理资源
   - 确认所有异常路径的资源释放

---

### 优先级低

7. **bundleName 长度限制**
   - 添加 bundleName 长度限制
   - 使用白名单校验格式

8. **空指针保护增强**
   - 使用 `std::shared_ptr` 或原子指针
   - 添加适当的锁保护

## 安全机制总结

### 权限检查机制

**权限常量**:
- `NEEDED_PERMISSION = "ohos.permission.BUNDLE_ACTIVE_INFO"`

**权限检查函数**:
- `CheckBundleIsSystemAppAndHasPermission()` - 检查系统应用和权限
- `CheckNativePermission()` - 检查 Native Token 权限
- `CheckSystemAppOrNativePermission()` - 统一入口

**调用者信息获取**:
- `IPCSkeleton::GetCallingTokenID()` - 获取 Token ID
- `IPCSkeleton::GetCallingUid()` - 获取 UID
- `IPCSkeleton::GetCallingFullTokenID()` - 获取完整 Token ID

**证据**:
- services/common/src/bundle_active_service.cpp:54: NEEDED_PERMISSION 定义

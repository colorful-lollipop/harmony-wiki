## 构建问题

### 问题 1：找不到编译器

**症状**：
```bash
$ gn gen out/Debug
ERROR at //build/lite/toolchain:xxx: toolchain not found
```

**原因**：
- 未设置 `OHOS_NDK_HOME` 环境变量
- NDK 路径不正确

**解决方案**：
```bash
# 设置 NDK 路径
export OHOS_NDK_HOME=/path/to/ohos-ndk

# 或使用绝对路径
gn gen out/Debug --ohos_ndk_path=/path/to/ohos-ndk
```

**证据**：`BUILD.gn:14`

---

### 问题 2：链接错误 - 找不到系统库

**症状**：
```bash
$ ninja -C out/Debug
ld: error: cannot find -liremote_object
```

**原因**：
- 依赖的系统组件未正确配置
- 构建路径不包含系统库

**解决方案**：
```bash
# 使用完整的构建命令
./build.sh --product-name rk3568 --build-target ohos_sdk

# 或手动设置库路径
export LD_LIBRARY_PATH=/path/to/ohos/symbols:$LD_LIBRARY_PATH
```

**证据**：`bundle.json:24-27`

---

### 问题 3：多线程编译失败

**症状**：
```bash
$ ninja -j8
FAILED: build.ninja:xxx: multiple rules generate xxx.o
```

**原因**：
- 源文件之间存在隐式依赖
- 头文件包含顺序问题

**解决方案**：
```bash
# 使用单线程编译
ninja -C out/Debug -j1

# 或清理后重新构建
rm -rf out/Debug
./build.sh --product-name rk3568
```

---

### 问题 4：符号重定义

**症状**：
```bash
$ ninja
ld: error: multiple definition of 'GetToken'
```

**原因**：
- `common_sources` 宏中包含重复的源文件
- 头文件保护宏（`#ifndef`）缺失或冲突

**解决方案**：
1. 检查 `common_sources` 中是否有重复
2. 确保头文件保护宏唯一
3. 清理构建缓存

## 运行时问题

### 问题 1：生成的代码无法编译

**症状**：
```bash
$ clang++ -std=c++17 generated_code.cpp
error: 'iremote_stub.h' file not found
```

**原因**：
- 生成的代码依赖 OpenHarmony 系统库
- 未指定正确的包含路径
- 未使用正确的编译选项

**解决方案**：
```bash
# 使用 IDL Tool 的编译脚本
# 生成的代码通常需要使用系统编译器配置
# 参考 bundle.json 中的依赖

# 手动编译示例
clang++ -std=c++17 \
    -I/path/to/ohos/samgr/interfaces/innerkits \
    -I/path/to/ohos/interfaces/innerkits/ ipc_core \
    -I/path/to/ohos/hiviewdfx/hilog/interfaces/innerkits/hilog_log \
    generated_code.cpp
```

**证据**：`bundle.json:25-27`

---

### 问题 2：链接生成的库时出错

**症状**：
```bash
$ clang++ -o libtest.so test_proxy.cpp test_stub.cpp
error: undefined reference to 'OnRemoteRequest'
```

**原因**：
- 生成的代码实现了 `OnRemoteRequest` 但未链接到 IPC 库
- 缺少必要的系统库

**解决方案**：
```bash
# 链接必要的系统库
clang++ -o libtest.so \
    test_proxy.cpp test_stub.cpp \
    -lhilog_ndk.z.so \
    -liremote_worker_ndk.z.so \
    -lipc_core_ndk.z.so \
    -lz \
    -lpthread
```

---

### 问题 3：运行时崩溃 - 段错误

**症状**：
```
Segmentation fault (core dumped)
```

**原因**：
- 生成的代码中存在空指针解引用
- 内存访问越界
- 初始化后使用

**解决方案**：
1. 检查生成的代码中的指针初始化
2. 添加空指针检查
3. 使用 Valgrind 或 AddressSanitizer 调试
4. 查看 dmesg 或 hilog 日志

**调试命令**：
```bash
# 使用 Valgrind
valgrind --leak-check=full --show-leak-kinds=all ./test_client

# 使用 AddressSanitizer
export ASAN_OPTIONS=halt_on_error=1
./test_client
```

## IDL 语法问题

### 问题 1：未定义的类型

**症状**：
```bash
$ idl test.idl
[test.idl:10] error:type 'UnknownType' not found
```

**原因**：
- 类型名称拼写错误
- 类型定义在使用的 IDL 文件中未找到

**解决方案**：
1. 检查类型名称拼写
2. 使用 `--package` 和 `-p` 正确指定包路径
3. 确保所有依赖的类型已定义

---

### 问题 2：语法错误 - 缺少分号

**症状**：
```bash
$ idl test.idl
[test.idl:15] error:unexpected token '}', expected ';'
```

**原因**：
- IDL 语法不正确
- 缺少语句终止符（`;`）

**解决方案**：
1. 检查 IDL 语法规范（[IDL-CPP.md](../IDL-CPP.md)）
2. 使用代码编辑器的高亮检查语法
3. 逐步添加定义，定位错误位置

---

### 问题 3：接口冲突

**症状**：
```bash
$ idl test.idl
[test.idl:20] error:interface 'ITest' already defined
```

**原因**：
- 同一接口被定义多次
- 名称空间冲突

**解决方案**：
1. 使用不同的接口名称
2. 使用包名空间避免冲突
3. 删除重复定义

---

## 元数据问题

### 问题 1：元数据生成失败

**症状**：
```bash
$ idl -c test.idl --dump-metadata
Generate metadata failed.
```

**原因**：
- AST 结构不完整或无效
- 类型检查失败

**解决方案**：
1. 先检查 IDL 文件语法：`idl -c test.idl`
2. 查看 AST 转储定位问题：`idl -c test.idl --dump-ast`
3. 检查接口类型（HDI vs SA）

---

### 问题 2：元数据文件损坏

**症状**：
```bash
$ idl -c test.idl
Metadata integrity check failed.
```

**原因**：
- 元数据文件被意外修改
- 文件传输错误

**解决方案**：
1. 重新生成元数据文件
2. 验证文件完整性
3. 检查磁盘空间

## 错误码处理

### Parser 错误码

| 错误信息 | 说明 | 修复方法 |
|---------|------|--------|
| `unexpected token` | IDL 语法错误 | 检查 IDL 文件语法 |
| `type 'XXX' not found` | 类型未定义 | 定义类型或检查包路径 |
| `interface 'XXX' already defined` | 接口重复定义 | 重命名或删除重复 |
| `parameter 'XXX' already defined` | 参数重复定义 | 重命名参数 |

## 性能优化建议

### 编译时间优化

1. **并行构建**：
   ```bash
   ninja -j$(nproc)  # 使用所有 CPU 核心
   ```

2. **增量构建**：
   ```bash
   ninja -C out/Debug
   ```

### 代码生成优化

1. **批量处理**：
   - 将多个 IDL 文件一次性传递
   - 减少工具启动开销

2. **输出目录管理**：
   - 使用绝对路径避免重复计算
   - 清理旧输出目录

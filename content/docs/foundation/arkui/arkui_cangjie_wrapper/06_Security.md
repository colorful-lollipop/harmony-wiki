# 安全风险评审 (Security Review)

## 概述

本文档对 arkui_cangjie_wrapper 进行安全风险评审，识别潜在攻击面、信任边界和安全风险。

### 评审范围

| 维度 | 覆盖 |
|------|------|
| **代码范围** | `kit/` + `ohos/` (排除 `test/`) |
| **外部依赖** | ace_engine, access_token, cangjie_ark_interop 等 |
| **运行时** | Cangjie 虚拟机 + ArkUI 引擎 |

### 评审局限性

- 本评审基于静态代码分析，未进行动态安全测试
- 外部依赖 (`ace_engine` 等) 的安全由其各自仓库负责
- Cangjie 语言本身的安全性由编译器保证

## 安全风险分析

### ✅ 已识别的安全控制

#### 1. API Level 控制

**证据**: `ohos/base/length.cj:27-37`

```cangjie
@!APILevel[
    since: "22",
    syscap: "SystemCapability.ArkUI.ArkUI.Full"
]
public interface Length {
    // ...
}
```

**说明**: 通过 `@APILevel` 宏控制 API 可访问性

#### 2. 权限检查

**依赖**: `access_token` 模块

**说明**: UI 组件依赖访问控制部件提供的授权与鉴权能力

#### 3. 业务异常

**证据**: `ohos/base/length.cj:37-45`

```cangjie
prop value: Float64 {
    get() {
        throw BusinessException(100001, "Internal error.")
    }
}
```

**说明**: 使用 `BusinessException` 进行错误处理

#### 4. 隐藏 API 标记

**证据**: `ohos/base/length.cj:67`

```cangjie
@!Hide
public func aboutToBeDeleted(): Bool {
    return this.clear()
}
```

**说明**: `@Hide` 宏标记内部 API

### ⚠️ 潜在风险点

#### 风险 1: 文本注入

| 项目 | 说明 |
|------|------|
| **风险** | 用户输入未经过滤直接渲染 |
| **触发条件** | Text/TextInput 组件显示未转义用户输入 |
| **影响** | XSS 攻击、UI 劫持 |
| **代码证据** | `ohos/arkui/component/text/` 组件 |
| **修复建议** | 对用户输入进行 HTML 转义或使用安全文本渲染 |

#### 风险 2: 路径遍历

| 项目 | 说明 |
|------|------|
| **风险** | 文件路径未验证导致目录遍历 |
| **触发条件** | Font/Image 组件使用用户提供路径 |
| **影响** | 读取任意文件、信息泄露 |
| **代码证据** | `ohos/arkui/ui_context/cj_font.cj` |
| **修复建议** | 对路径参数进行规范化验证 |

#### 风险 3: 网络数据安全

| 项目 | 说明 |
|------|------|
| **风险** | 网络资源未验证来源 |
| **触发条件** | Image/Video/Web 组件加载网络资源 |
| **影响** | 中间人攻击、恶意内容注入 |
| **代码证据** | `ohos/arkui/component/image/` 组件 |
| **修复建议** | 使用 HTTPS、添加 CSP 头 |

#### 风险 4: 状态数据泄露

| 项目 | 说明 |
|------|------|
| **风险** | @State/@Link 数据可能被其他组件访问 |
| **触发条件** | 状态数据未正确封装 |
| **影响** | 数据泄露、状态篡改 |
| **代码证据** | `ohos/arkui/state_management/` |
| **修复建议** | 加强状态访问控制 |

#### 风险 5: 资源耗尽

| 项目 | 说明 |
|------|------|
| **风险** | 大量状态更新导致 UI 线程阻塞 |
| **触发条件** | 短时间大量状态修改 |
| **影响** | 应用卡顿、ANR |
| **代码证据** | 状态管理更新机制 |
| **修复建议** | 添加节流/防抖机制 |

## 安全最佳实践

### 开发者建议

1. **用户输入处理**
   - 始终验证和清理用户输入
   - 敏感数据使用加密存储

2. **状态管理**
   - 使用 @Prop/@Link 代替直接共享状态
   - 敏感状态使用 @ObjectLink 包装

3. **网络请求**
   - 使用 HTTPS
   - 验证服务器证书
   - 添加请求签名

4. **文件访问**
   - 使用应用沙箱目录
   - 验证文件路径
   - 限制文件权限

5. **权限申请**
   - 遵循最小权限原则
   - 动态申请敏感权限

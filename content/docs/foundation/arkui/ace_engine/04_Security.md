## 攻击面分析

### 1.1 外部输入点

Ace Engine 接受以下外部输入：

| 输入类型 | 来源 | 风险等级 | 证据 |
|----------|------|----------|------|
| **N-API 参数** | JS/ArkTS 调用 | 高 | `interfaces/napi/kits/` |
| **组件属性** | 声明式 UI 描述 | 中 | `frameworks/bridge/declarative_frontend/` |
| **用户输入** | 触摸/手势事件 | 中 | `frameworks/core/components_ng/gestures/` |
| **资源加载** | 图片/字体/布局文件 | 高 | `adapter/ohos/resource/` |
| **路由参数** | 页面跳转数据 | 中 | `interfaces/napi/kits/router/` |
| **拖拽数据** | 跨应用拖拽 | 中 | `interfaces/napi/kits/drag_controller/` |
| **截图请求** | 组件快照 | 中 | `interfaces/napi/kits/component_snapshot/` |

### 1.2 暴露接口

| 接口类型 | 位置 | 风险 |
|----------|------|------|
| **N-API 模块** | `interfaces/napi/kits/*/` | ~75+ 个模块 |
| **系统能力调用** | `adapter/ohos/` | 窗口、输入、资源 |
| **IPC 接口** | `interfaces/inner_api/ui_session/` | SA 服务通信 |
| **文件操作** | 资源加载路径 | 路径遍历 |

## 信任边界

### 2.1 信任层级

```
┌─────────────────────────────────────────────────────────┐
│  信任边界层级                                             │
│                                                          │
│  Level 1: 应用程序层 (高信任)                            │
│     - 同一应用内的 UI 描述                               │
│     - 应用声明的资源文件                                  │
│                                                          │
│  Level 2: 框架层 (中信任)                                │
│     - N-API 参数校验后的数据                             │
│     - 组件树状态                                         │
│                                                          │
│  Level 3: 系统服务层 (高信任)                             │
│     - 已通过权限检查的系统调用                           │
│     - 窗口管理、输入事件                                 │
│                                                          │
│  Level 4: 外部输入 (低信任)                               │
│     - 跨应用数据                                         │
│     - 网络资源                                           │
│     - 用户输入                                           │
└─────────────────────────────────────────────────────────┘
```

### 2.2 边界检查点

| 检查点 | 位置 | 检查内容 |
|--------|------|----------|
| **N-API 入口** | `interfaces/napi/kits/*/` | 参数类型、范围、空值 |
| **IPC 调用** | `adapter/ohos/communication/` | 调用者身份、权限 |
| **资源路径** | `adapter/ohos/resource/` | 路径遍历 |
| **权限验证** | `Security::AccessToken` | 系统应用标识 |

## 安全机制

### 3.1 权限控制

**系统应用验证**:

```cpp
// 证据来源: interfaces/napi/kits/plugincomponent/js_plugin_component.cpp
IPCSkeleton::GetSelfTokenID()
Security::AccessToken::TokenIdKit::IsSystemAppByFullTokenID()
```

**验证流程**:
1. 获取调用者 TokenID
2. 判断是否为系统应用
3. 根据结果授权或拒绝

### 3.2 参数校验

| 校验类型 | 位置 | 证据 |
|----------|------|------|
| **空值检查** | N-API 入口 | `napi_*` 函数返回值检查 |
| **类型检查** | `napi_get_value_*` | 类型转换前验证 |
| **范围检查** | 组件属性 | LayoutProperty 约束 |
| **字符串长度** | 资源路径 | 文件路径长度限制 |

### 3.3 符号可见性

```gn
# BUILD.gn:43-44
cflags = [
  "-fvisibility=hidden",      # 隐藏非导出符号
]
```

**作用**: 减少攻击面，仅暴露必要符号

## 风险清单

### 4.1 高风险项

#### 风险 1: N-API 参数校验不足

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-001 |
| **风险类型** | 输入验证 |
| **风险等级** | 高 |
| **攻击面** | `interfaces/napi/kits/*/` |

**证据**:
- N-API 函数入口使用 `napi_get_value_*` 直接取值
- 部分模块缺少参数有效性检查

**可利用路径**:
```
JS 调用 → napi_get_value_string_utf8 → 缓冲区溢出
```

**影响**: 拒绝服务、内存损坏

**修复建议**:
- 所有 N-API 入口添加参数校验
- 使用 `napi_check_args` 模式
- 添加边界检查

---

#### 风险 2: 资源路径遍历

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-002 |
| **风险类型** | 路径遍历 |
| **风险等级** | 高 |
| **攻击面** | `adapter/ohos/resource/` |

**证据**:
- 资源加载可能接受外部路径
- 未验证 `../` 路径遍历

**可利用路径**:
```
加载资源 → 构造路径 "app/../../etc/passwd" → 越权访问
```

**影响**: 敏感文件泄露

**修复建议**:
- 实现路径标准化
- 验证路径前缀
- 使用沙箱路径

---

#### 风险 3: 组件属性注入

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-003 |
| **风险类型** | 数据验证 |
| **风险等级** | 中 |
| **攻击面** | `frameworks/bridge/declarative_frontend/` |

**证据**:
- 声明式 UI 描述直接解析
- 部分属性缺少类型约束

**可利用路径**:
```
UI 描述 → 解析器 → 构造恶意属性 → 渲染异常
```

**影响**: 渲染崩溃、功能异常

**修复建议**:
- 属性白名单校验
- 异常值默认值降级

---

### 4.2 中风险项

#### 风险 4: 拖拽数据越权

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-004 |
| **风险类型** | 权限控制 |
| **风险等级** | 中 |
| **攻击面** | `interfaces/napi/kits/drag_controller/` |

**证据**:
- 拖拽操作接受跨应用数据
- 拖拽内容校验依赖调用者

**可利用路径**:
```
拖拽数据 → 恶意内容 → 注入敏感信息
```

**影响**: 数据泄露

**修复建议**:
- 拖拽数据签名验证
- 内容类型白名单

---

#### 风险 5: 截图接口滥用

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-005 |
| **风险类型** | 信息泄露 |
| **风险等级** | 中 |
| **攻击面** | `interfaces/napi/kits/component_snapshot/` |

**证据**:
- `componentSnapshot` 接口可截取任意组件
- 未限制可截图范围

**可利用路径**:
```
截图 API → 截取敏感组件 → 保存/传输
```

**影响**: 隐私泄露

**修复建议**:
- 限制可截图组件类型
- 添加水印标识

---

#### 风险 6: IPC 通信伪造

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-006 |
| **风险类型** | IPC 安全 |
| **风险等级** | 中 |
| **攻击面** | `interfaces/inner_api/ui_session/` |

**证据**:
- UI Content 服务通过 IPC 通信
- Binder 事务处理外部请求

**可利用路径**:
```
伪造 IPC 请求 → 越权操作 UI Content
```

**影响**: UI 劫持、权限提升

**修复建议**:
- 验证调用者身份
- IPC 参数签名

---

### 4.3 低风险项

#### 风险 7: 日志信息泄露

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-007 |
| **风险类型** | 信息泄露 |
| **风险等级** | 低 |
| **攻击面** | `adapter/ohos/hisysevent/` |

**证据**:
- 性能日志可能包含敏感信息
- Debug 模式下日志级别较低

**影响**: 内部信息暴露

**修复建议**:
- 生产环境日志脱敏
- 敏感字段过滤

## 修复建议

### 5.1 优先级排序

| 优先级 | 风险 ID | 建议 |
|--------|---------|------|
| **P0** | SEC-001 | N-API 参数校验增强 |
| **P0** | SEC-002 | 路径遍历防护 |
| **P1** | SEC-003 | 属性注入防护 |
| **P1** | SEC-004 | 拖拽数据校验 |
| **P2** | SEC-005 | 截图范围限制 |
| **P2** | SEC-006 | IPC 身份验证 |
| **P3** | SEC-007 | 日志脱敏 |

### 5.2 通用安全准则

| 准则 | 描述 |
|------|------|
| **最小权限** | 只请求必要系统能力 |
| **输入验证** | 所有外部输入必须校验 |
| **输出编码** | 敏感数据输出时脱敏 |
| **沙箱隔离** | 资源访问限制在沙箱内 |
| **日志审计** | 安全相关操作记录日志 |

### 1.2 模块职责

| 层级 | 模块 | 职责 | 本模块角色 |
|------|------|------|-----------|
| **应用层** | 各类媒体应用 | 提供用户界面 | 无 |
| **框架层** | castengine_cast_framework | N-API 接口、JS 绑定 | 被依赖方 |
| **服务层** | **本模块** | **核心投屏逻辑** | **核心实现** |
| **服务层** | castengine_wifi_display | WiFi Display 协议 | 同级模块 |
| **服务层** | castengine_dlna | DLNA 协议 | 同级模块 |

## 2. 功能边界

### 2.1 包含的功能

#### 核心功能

| 功能域 | 具体功能 | 说明 |
|--------|----------|------|
| **会话管理** | 会话生命周期管理 | 创建、连接、断开、销毁 |
| | 设备管理 | 添加、移除、查询设备 |
| | 状态机管理 | 状态转换、事件处理 |
| **协议处理** | RTSP 协议实现 | M1-M6 握手、参数协商 |
| | 加密协商 | AES-128-CTR/GCM |
| | 能力交换 | 音视频格式、UIBC 能力 |
| **通道管理** | SoftBus 通道 | 软总线传输 |
| | TCP 通道 | 标准 TCP 传输 |
| | VTP 通道 | 虚拟传输协议 |
| | 多通道复用 | 音视频控制分离 |
| **流媒体** | 播放控制 | Play/Pause/Seek/Stop |
| | 播放状态同步 | 双向状态通知 |
| | 本地文件传输 | 文件通道实现 |
| | 在线媒体支持 | URL 播放 |
| **镜像** | 屏幕采集 | 视频帧采集 |
| | 音频采集 | 系统音频采集 |
| | 反向控制 | Sink 端输入回传 |

#### 辅助功能

| 功能域 | 具体功能 | 说明 |
|--------|----------|------|
| **权限控制** | 系统权限检查 | Mirror/Stream 权限 |
| | PID 白名单 | 进程级访问控制 |
| **工具类** | 加密解密 | AES 实现 |
| | 状态机 | 通用状态机框架 |
| | 消息队列 | 线程间通信 |
| | 定时器 | 超时处理 |

### 2.2 不包含的功能

| 功能 | 说明 | 归属模块 |
|------|------|----------|
| **N-API/JS 接口** | JavaScript 绑定层 | castengine_cast_framework |
| **UI 界面** | 投屏 UI、设置界面 | 应用层 |
| **设备发现** | 设备搜索、配对 | cast_engine_service/device_manager |
| **WiFi Display** | WFD 协议实现 | castengine_wifi_display |
| **DLNA** | DLNA 协议实现 | castengine_dlna |
| **视频编码** | H.264/H.265 编码 | 系统 media_codec |
| **音频编解码** | AAC/PCM 编解码 | 系统 audio_framework |
| **网络管理** | WiFi P2P 管理 | 系统 wifi 服务 |

## 3. 核心能力

### 3.1 技术能力矩阵

| 能力 | 支持 | 说明 |
|------|------|------|
| **多设备连接** | ✅ | 支持同时连接多个 Sink 设备 |
| **双端播控** | ✅ | Source 和 Sink 均可控制播放 |
| **协议自适应** | ✅ | 自动选择 SoftBus/TCP/VTP |
| **加密传输** | ✅ | AES-128-CTR/GCM |
| **UIBC 回传** | ✅ | 用户输入反向通道 |
| **断线重连** | ⚠️ | 依赖上层实现 |
| **多路并发** | ✅ | 支持多路音视频通道 |

### 3.2 性能指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| **连接建立时间** | < 3s | 从发起连接到可播放 |
| **镜像延迟** | < 100ms | 端到端显示延迟 |
| **流媒体缓冲** | < 2s | 首次缓冲时间 |
| **并发会话** | ≥ 4 | 同时支持的会话数 |

### 3.3 兼容性

| 兼容性项 | 支持情况 |
|----------|----------|
| **OpenHarmony 版本** | 3.2+ |
| **设备类型** | 手机、平板、TV、音箱 |
| **网络类型** | WiFi P2P、WiFi LAN、以太网 |

## 4. 非功能特性

### 4.1 可靠性

| 特性 | 实现 |
|------|------|
| **异常处理** | 状态机驱动，异常状态自动恢复 |
| **资源释放** | RAII 模式，确保资源不泄漏 |
| **超时机制** | 连接、操作均有超时保护 |

### 4.2 安全性

| 特性 | 实现 |
|------|------|
| **权限控制** | 系统权限 + PID 白名单 |
| **传输加密** | AES-128 会话加密 |
| **输入校验** | 参数范围检查、类型校验 |

### 4.3 可维护性

| 特性 | 实现 |
|------|------|
| **模块化设计** | 清晰的模块边界和接口 |

| **状态可视化** | 状态机支持状态查询 |

## 5. 使用场景

### 5.1 典型场景

#### 场景一：手机投屏到电视（镜像）
```
用户操作: 手机点击"投屏" → 选择电视 → 开始镜像
系统流程:
1. 应用层调用 CastEngine N-API
2. N-API 调用本模块创建 Session
3. Session 通过 device_manager 发现设备
4. 建立 RTSP 连接，协商参数
5. 创建音视频 Channel
6. 开始屏幕采集和传输
7. 电视端解码显示
```

#### 场景二：手机推送视频到电视（流媒体）
```
用户操作: 手机选择视频 → 点击"在电视上播放"
系统流程:
1. 应用层调用 Stream Cast API
2. 创建 Stream Session
3. 建立文件传输通道
4. 电视端通过文件通道读取视频
5. 电视端本地播放
6. 支持手机端控制播放进度
```

### 5.2 不支持的场景

| 场景 | 原因 | 替代方案 |
|------|------|----------|
| 跨互联网投屏 | 依赖局域网 SoftBus | 使用其他协议 |
| 多人同时控制 | 未实现冲突解决 | 单控制端 |
| 4K 高帧率镜像 | 受编码性能限制 | 降低分辨率 |

# 常见构建/运行/调试问题

> 文档版本: 1.0.0

## 目的

本文档提供 CastEngine 框架的常见问题、调试方法和定位路径，帮助开发者快速解决问题。

## 构建相关问题

### Q1: 编译时出现 "undefined reference" 错误

**症状**:
```
undefined reference to 'CastSessionManager'
```

**原因**:
- 缺少必要的头文件包含
- 头文件搜索路径配置错误

**解决方法**:
1. 确认 include 路径包含 `interfaces/inner_api/include`
2. 检查 `.gni` 文件中的 `include_dirs` 配置
3. 清理构建缓存：`hb clean`

**相关文件**:
- `interfaces/inner_api/BUILD.gn:16-18`

---

### Q2: 链接时出现 "cannot find -lxxx" 错误

**症状**:
```
ld: cannot find -lcast_engine_client
```

**原因**:
- 内部依赖顺序错误
- 库未正确链接

**解决方法**:
1. 检查 `deps` 配置中的依赖顺序
2. 确保先依赖静态库，再依赖共享库
3. 检查 `external_deps` 中的系统库是否存在

**相关文件**:
- `interfaces/kits/js/BUILD.gn:43-46`

---

### Q3: 编译失败，提示 "insufficient permissions"

**症状**:
```
Error: insufficient permissions to access /system/lib64/
```

**原因**:
- 构建环境权限不足
- 非 root 用户构建系统镜像

**解决方法**:
1. 使用正确的构建环境（Docker、虚拟机）
2. 确保构建用户有足够权限
3. 检查 SELinux/AppArmor 策略

## 运行时问题

### Q4: 应用启动时无法加载 cast 模块

**症状**:
```
Error: module 'cast' not found
```

**可能原因**:
1. libcast.z.so 未安装到系统
2. 模块路径配置错误
3. bundle.json5 配置问题

**定位步骤**:
1. 使用 `hdc shell ls /system/lib64/module/` 检查 libcast.z.so 是否存在
2. 检查文件权限：`hdc shell ls -l /system/lib64/module/libcast.z.so`
3. 使用 `hdc shell pm list packages | grep cast` 检查包配置
4. 使用 `hdc shell ps -ef | grep cast` 检查服务进程

**相关文件**:
- `interfaces/kits/js/BUILD.gn`
- `bundle.json`

---

### Q5: 调用 startDiscovery() 返回 ERR_NO_PERMISSION

**症状**:
```
startDiscovery failed : no permission
Error code: -1003
```

**可能原因**:
1. 应用未声明权限：`ohos.permission.ACCESS_CAST_ENGINE_STREAM`
2. 权限未授予
3. 权限 Token 验证失败

**定位步骤**:
1. 检查应用 `module.json5` 权限声明
2. 使用 `hdc shell pm grant permission` 检查权限状态
3. 使用 `hdc shell bm dump -n <packageName>` 查看权限详情

**权限检查代码**:
- `service/src/session/src/utils/src/permission.cpp:55-83`

---

### Q6: createCastSession() 成功但 deviceFound 事件不触发

**症状**:
```
会话创建成功，但设备列表为空
```

**可能原因**:
1. 设备发现未启动
2. 网络问题
3. 适配器服务未运行

**定位步骤**:
1. 确认调用了 `startDiscovery()` 并且成功
2. 检查 `deviceFound` 事件监听器是否正确注册
3. 使用日志查看发现过程

**日志过滤**:
```bash
hdc shell hilog -T Cast-Napi-SessionManager | grep "discovery"
```

**相关代码**:
- `interfaces/kits/js/src/napi_cast_session_manager.cpp:45-49`

---

### Q7: 镜像播放器卡顿或黑屏

**症状**:
```
MirrorPlayer.play() 调用成功，但远程设备黑屏
```

**可能原因**:
1. Surface 未正确设置
2. 编码器未初始化
3. 网络连接问题
4. 远程设备不支持当前编码格式

**定位步骤**:
1. 检查 Surface 是否有效创建：`interfaces/kits/js/src/napi_mirror_player.cpp:247-298`
2. 使用 `hdc shell hidumper -s CastEngine` 查看 Surface 状态
3. 检查网络连接状态
4. 查看服务端日志

**相关代码**:
- `interfaces/kits/js/src/napi_mirror_player.cpp`
- `service/src/session/src/mirror/src/mirror_player_impl.cpp`

---

### Q8: 流播放器无法加载网络媒体

**症状**:
```
StreamPlayer.load() 调用成功，但播放失败
Error code: 2001 (network connection failed)
```

**可能原因**:
1. URL 格式错误
2. 网络不可达
3. HTTP 状态码错误
4. 代理配置问题

**定位步骤**:
1. 检查 URL 格式是否正确
2. 使用 `hdc shell ping <url>` 测试网络可达性
3. 使用 `hdc shell ifconfig` 查看网络配置
4. 查看 RTSP 解析日志

**错误码定义**:
- `interfaces/inner_api/include/cast_engine_errors.h:59-77`

## 调试方法

### 启用详细日志

**日志系统**: HiLog

**设置日志级别**:

```bash
# 设置所有标签的日志级别
hdc shell hilog -b Cast-Napi-SessionManager D

# 查看实时日志
hdc shell hilog | grep Cast

# 保存日志到文件
hdc shell hilog > /data/local/tmp/cast.log
```

**主要日志标签**:
- `Cast-Napi-SessionManager`
- `Cast-Napi-Session`
- `Cast-Napi-StreamPlayer`
- `Cast-Napi-MirrorPlayer`
- `Cast-Permission`
- `Cast-Discovery`
- `Cast-Service`

### 使用 HiDumper

**查看 SA 状态**:

```bash
# 查看 CastEngine SA 状态
hdc shell hidumper -s CastEngine

# 查看所有 SA
hdc shell hidumper -l

# 导出详细信息
hdc shell hidumper -s CastEngine -a
```

**有用的命令**:
- `dump` - 查看服务内部状态
- `dump -a` - 查看所有信息
- `list` - 列出所有服务

### 使用 IPC 调试工具

**查看 Binder 事务**:

```bash
# 使用调试工具查看 IPC 调用
hdc shell binderDebug

# 或者使用 strace
hdc shell strace -p <pid>
```

### 抓包分析

**网络抓包**:

```bash
# 使用 tcpdump 抓取网络包
hdc shell tcpdump -i any -w /data/local/tmp/cast.pcap

# 在主机上分析
wireshark cast.pcap
```

**RTSP 分析**:
- 查看 RTSP OPTIONS/DESCRIBE/SETUP 消息
- 检查 SDP 内容
- 验证媒体格式协商

## 日志分析技巧

### 1. 过滤特定标签

```bash
# 只看会话管理器日志
hdc shell hilog -T Cast-Napi-SessionManager

# 只看错误日志
hdc shell hilog -T * | grep -E "ERROR|FATAL"

# 排除某个标签
hdc shell hilog -T * | grep -v Cast-Napi-StreamPlayer
```

### 2. 时间范围过滤

```bash
# 查看最近 5 分钟的日志
hdc shell hilog -t 300

# 查看特定时间段的日志
hdc shell hilog -T * --start="2026-02-06 10:00:00" --end="2026-02-06 10:05:00"
```

### 3. 日志级别说明

| 级别 | 说明 | 使用场景 |
|-----|------|---------|
| FATAL | 致命错误，立即退出 | 系统崩溃 |
| ERROR | 错误，需要处理 | 功能失败 |
| WARN | 警告，需要注意 | 潜在问题 |
| INFO | 信息，正常流程 | 关键节点 |
| DEBUG | 调试信息 | 开发和调试 |
| TRACE | 追踪信息 | 性能分析 |

## 性能优化建议

### 1. 减少不必要的日志

```cpp
// 错误示例（生产代码中避免）
CLOGI("Frequent debug info");  // 应该用 CLOGD 或移除
```

### 2. 使用异步处理避免阻塞

```cpp
// 正确：使用异步工作队列
auto asyncTask = std::make_shared<NapiAsyncTask>();
NapiAsyncWork::Enqueue(env, asyncTask, "TaskName", executor, complete);

// 错误：直接在主线程执行耗时操作
std::this_thread::sleep_for(std::chrono::seconds(5));  // 阻塞主线程
```

### 3. 合理使用共享内存

```cpp
// 正确：及时释放共享内存
sharedMemory->Close();

// 错误：长期持有共享内存引用
// 导致内存无法回收
```

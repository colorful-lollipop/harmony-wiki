# 系统架构

## 2.1 整体架构概览

应用文件服务采用分层架构设计，从上至下依次为接口层、框架层、服务层和工具层。每一层都有明确的职责边界，层与层之间通过清晰定义的接口进行交互。这种分层设计确保了系统的可维护性和可扩展性，同时为多种编程语言提供了一致的编程接口。

### 2.1.1 架构分层

**接口层（interfaces/）** 是整个系统对外暴露编程接口的层次。该层负责将底层的复杂逻辑封装为易用的 API，包括 JS N-API、NDK C 接口、ANI 接口、泰河接口、仓颉接口等多种形式。接口层的设计目标是让应用开发者能够以最少的代码完成文件分享和备份恢复功能。

**框架层（frameworks/）** 是实现具体业务逻辑的层次。框架层接收接口层的调用请求，执行参数校验、权限验证等前置处理，然后将请求转发给服务层。框架层还负责实现备份扩展（Backup Extension）的核心逻辑，包括数据打包、解压、扩展生命周期管理等。

**服务层（services/）** 是以系统能力（SA）方式运行的独立进程。服务层负责调度管理备份恢复任务、维护会话状态、协调数据传输。服务层的设计充分考虑了稳定性和性能要求，支持异常恢复、超时控制等机制。

**工具层（utils/）** 提供通用的功能模块，被其他层次复用。工具层包括错误处理、日志、JSON 解析、文件操作、进程管理等基础功能。这些模块经过精心设计，具有良好的独立性和可测试性。

## 2.2 数据流分析

### 2.2.1 文件分享数据流

文件分享的数据流相对简单，主要涉及权限验证和 URI 生成两个核心步骤。分享方应用调用授权接口时，系统首先验证调用者是否对目标文件具有访问权限，然后生成带有授权信息的 URI 返回给调用者。被授权方通过该 URI 访问文件时，系统会验证 URI 中的授权信息，确保访问在授权范围内。

### 2.2.2 备份操作数据流

## 2.3 线程模型

### 2.3.1 备份服务线程池配置

备份服务使用多线程并发处理任务，主要包括以下线程池：

**Extension 线程池**（大小为 1）：专门用于执行备份扩展的回调处理。由于备份扩展在独立的进程中运行，Extension 线程池主要用于管理扩展的生命周期和处理 IPC 消息。单线程设计确保了同一时刻只有一个扩展回调在执行，避免了并发冲突。

**SA 线程池**（大小为 1）：专门用于执行系统能力相关的心跳和回调处理。该线程池负责与系统能力框架的交互，处理服务状态变更等事件。

**回调扫描结果线程池**（大小为 1）：专门用于处理扩展返回的扫描结果。当扩展完成目录扫描后，扫描结果通过此线程池返回给调用方。

**获取数据大小线程池**（大小为 1）：专门用于计算待备份数据的大小。由于数据大小计算可能涉及大量文件扫描，该操作被放入独立线程池执行，避免阻塞主线程。

### 2.3.3 线程安全设计

备份服务在设计时充分考虑了线程安全问题。主要的同步机制包括：

**互斥锁**：会话状态、扩展连接状态等关键数据使用互斥锁保护。获取这些数据前必须先获得对应的锁，操作完成后释放锁。互斥锁的使用避免了竞态条件，但可能导致线程阻塞。

**原子变量**：部分状态标志使用原子变量实现无锁同步，如会话开始标志、扩展连接状态等。原子变量的使用避免了复杂的锁管理，同时保证了状态更新的原子性。

**条件变量**：等待特定状态时使用条件变量进行线程间同步。例如等待扩展连接完成、等待数据准备就绪等场景都使用了条件变量。条件变量配合互斥锁使用，实现高效的线程协作。

**单线程执行模型**：部分关键流程采用单线程执行模型，确保操作的有序性。例如会话内的数据处理必须在同一线程中顺序执行，不能并行。

## 2.5 信任边界与安全假设

### 2.5.1 信任边界

应用文件服务的信任边界主要包括以下几个层次：

**进程边界**：应用进程与备份服务进程之间的 IPC 调用是主要的信任边界。应用进程中的代码不可信，所有来自应用进程的参数都需要经过严格校验。备份服务进程中的代码是可信的，负责执行核心业务逻辑。

**用户边界**：不同用户之间的数据相互隔离。用户 ID 用于标识数据的归属，跨用户的数据访问需要额外的权限验证。

**应用边界**：不同应用之间的数据默认相互隔离。应用沙箱机制确保应用只能访问自己的数据，除非获得明确的权限授权。

### 2.5.2 安全假设

本模块的安全设计基于以下假设：

假设 1：系统能力框架（SAF/SAMGR）是安全的。系统能力框架负责管理 SA 的注册、发现和调用，其本身的安全性由系统保证。

假设 2：内核和驱动是安全的。文件系统操作最终由内核执行，内核的访问控制机制是安全的最后一道防线。

假设 3：密钥存储是安全的。用于数据加密的密钥存储在安全硬件中或由系统密钥管理服务保护。

假设 4：代码签名是有效的。所有加载执行的代码都经过签名验证，防止恶意代码注入。

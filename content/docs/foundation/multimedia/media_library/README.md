# MediaLibrary Wiki 使用指南

## 文档概述

本文档为 MediaLibrary (medialibrary_standard) 项目的工程 Wiki，提供完整的项目文档覆盖。Wiki 内容基于代码分析自动生成，关键结论均可追溯到源代码证据。

## 覆盖范围

### ✅ 已覆盖领域

| 领域 | 覆盖内容 | 证据来源 |
|-----|---------|---------|
| **项目定位** | 核心能力、系统依赖、版本信息 | README.md, bundle.json |
| **目录结构** | 模块划分、职责定义 | 目录遍历 + 代码分析 |
| **架构设计** | 组件图、数据流、线程模型 | 源码架构 + 接口分析 |
| **N-API 接口** | JS API 清单、参数、返回值 | 接口头文件 + N-API 注册 |
| **内部 API** | 模块接口、依赖方向 | inner_api + 实现代码 |
| **构建系统** | GN Targets、产物清单 | BUILD.gn, media_library.gni |
| **安全风险** | 攻击面、信任边界、风险清单 | 安全相关代码分析 |

### ❌ 未覆盖领域

| 领域 | 原因 | 替代方案 |
|-----|------|---------|
| 测试代码 | 约束要求忽略测试内容 | 参考单元测试目录 |
| 运行时行为 | 需要真实设备验证 | 参考 DFX 日志分析 |
| 性能数据 | 需要基准测试环境 | 参考 hisysevent.yaml |

## 文档更新方式

### 触发更新

文档应在以下情况更新：

1. **新增 N-API 接口**
   - 更新 `03_N-API_Reference.md` 接口清单
   - 添加 API 注册证据

2. **修改模块职责**
   - 更新 `01_Directory_Structure.md`
   - 更新 `04_Inner_API.md`

3. **调整构建配置**
   - 更新 `05_Build_System.md`
   - 更新 feature flags 列表

4. **发现安全问题**
   - 在 `06_Security_Review.md` 添加风险项

### 更新流程

```markdown
1. 在 `wiki/_work/NOTES.md` 记录发现
2. 更新对应的 Wiki 文档
3. 在文档中添加代码证据（路径 + 符号）
4. 更新 SUMMARY.md 链接（如需要）
```

### 证据规范

所有关键结论必须包含：

```
**证据**:
-markdown 文件路径: `path/to/file.cpp:line`
- 关键符号: `ClassName::MethodName` 或 `FUNCTION_NAME`
- 最小必要代码片段或调用链描述
```

## 反馈渠道

### 文档问题反馈

1. **代码证据缺失**: 在 `wiki/_work/NOTES.md` 记录
2. **内容错误**: 提交 Issue 描述问题
3. **新增需求**: 提交 Feature Request

### 贡献方式

1. Fork 仓库
2. 修改 `wiki/` 下对应文档
3. 遵循证据规范添加代码引用
4. 提交 PR 并关联 Issue

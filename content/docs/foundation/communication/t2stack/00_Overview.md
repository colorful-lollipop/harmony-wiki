# T2Stack 项目概览

## 项目定位

T2Stack 是面向智能终端场景的**极简网络协议栈**及其配套中间件的统称，属于 OpenHarmony 软总线（Soft Bus）下面的关键传输与设备发现模块。

```
┌─────────────────────────────────────────────────────────────┐
│                      OpenHarmony 系统                        │
├─────────────────────────────────────────────────────────────┤
│                       软总线 (Soft Bus)                      │
│  ┌───────────────────────────────────────────────────────┐  │
│  │                    T2Stack                            │  │
│  │  ┌──────────┐ ┌──────────┐ ┌──────────────────────┐  │  │
│  │  │  Fillp   │ │  DFile   │ │      NStackX        │  │  │
│  │  │(流传输)   │ │(文件传输) │ │     (设备发现)       │  │  │
│  │  └──────────┘ └──────────┘ └──────────────────────┘  │  │
│  │       ↓            ↓               ↓                 │  │
│  │  ┌─────────────────────────────────────────────────┐ │  │
│  │  │              NStackX Util (公共模块)            │ │  │
│  │  │  ┌──────────┐ ┌──────────┐ ┌──────────┐        │ │  │
│  │  │  │ 事件机制  │ │ Socket   │ │  定时器   │        │ │  │
│  │  │  └──────────┘ └──────────┘ └──────────┘        │ │  │
│  │  └─────────────────────────────────────────────────┘ │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

## 核心能力

### 1. 文件传输能力 (DFile)

提供设备间文件传输基本能力，并在传输中提供多种优化：

| 能力 | 说明 | 代码证据 |
|------|------|----------|
| **基础传输** | 点对点文件传输，支持大文件 | `nstackx_dfile.h:312-313` (NSTACKX_DFileServer) |
| **大小文件协同** | 大小文件并行传输优化 | `nstackx_dfile.h:381-382` (NSTACKX_DFileSendFiles) |
| **小文件打包** | 多个小文件打包成一个传输 | `nstackx_dfile.h:396-410` (tarFlag) |
| **多路径传输** | 同时使用 WiFi 和其他链路 | `nstackx_dfile.h:325-326` (MpV2 接口) |
| **断点续传** | 支持传输中断后继续 | `nstackx_dfile.h:91` (CAPS_RESUMABLE_TRANS) |
| **文件加密** | 传输过程中数据加密 | `nstackx_dfile.h:308-313` (key 参数) |

### 2. 流传输能力 (Fillp)

主要针对视频流、音频流传输场景，实现以下竞争力方案：

| 方案 | 说明 | 代码证据 |
|------|------|----------|
| **半可靠传输** | 可配置丢帧策略，平衡可靠性与实时性 | `fillpinc.h:944-968` (FillpAppFlowControlSt) |
| **自适应丢帧** | 网络差时自动丢弃非关键帧（P帧/B帧） | `fillpinc.h:967` (differTransmit) |
| **带宽评估** | 动态评估网络带宽，调整发送速率 | `fillpinc.h:834-839` (maxRate, initialRate) |
| **码率自适应** | 根据网络状况自动调整码率 | `fillpinc.h:949-954` (maxRecvRate) |
| **弱网检测** | 动态缓存，应对弱网环境 | `fillpinc.h:973-995` (AppTimerSt) |
| **FEC 冗余** | 前向纠错，减少重传 | `fillpinc.h:851-854` (fecEnable) |

### 3. 设备发现能力 (NStackX)

提供局域网下设备之间发现能力：

| 能力 | 说明 | 代码证据 |
|------|------|----------|
| **设备广播** | 周期性广播设备信息 | `nstackx.h:261` (NSTACKX_SendNotification) |
| **单播响应** | 可靠的单播响应机制 | `nstackx.h:245` (NSTACKX_SendDiscoveryRsp) |
| **能力过滤** | 根据设备能力过滤发现结果 | `nstackx.h:115` (NSTACKX_SetFilterCapability) |
| **设备列表缓存** | 本地缓存发现的设备列表 | `nstackx.h:194` (NSTACKX_GetDeviceList) |
| **业务数据透传** | 在发现报文中携带业务数据 | `nstackx.h:146` (NSTACKX_RegisterServiceData) |

## 运行环境

### 支持的系统类型

T2Stack 支持 OpenHarmony 的三种系统类型：

| 系统类型 | 支持状态 | 说明 |
|----------|----------|------|
| **mini** | ✅ 支持 | 轻量级系统，资源受限 |
| **small** | ✅ 支持 | 小型系统，平衡功能与资源 |
| **standard** | ✅ 支持 | 标准系统，功能完整 |

### 支持的内核

| 内核 | 支持状态 | 代码证据 |
|------|----------|----------|
| **LiteOS-A** | ✅ 支持 | `BUILD.gn:104-108` (ohos_kernel_type == "liteos_a") |
| **LiteOS-M** | ✅ 支持 | `BUILD.gn:54` (liteos_m 分支) |
| **Linux** | ✅ 支持 | `BUILD.gn:88-96` (linux 分支) |

### 资源占用

| 资源项 | 大小 | 来源 |
|--------|------|------|
| **ROM** | ~3000KB | `bundle.json:27` |
| **RAM** | ~40MB | `bundle.json:28` |

## 关键概念

### 1. 会话 (Session)

文件传输和流传输都以会话（Session）为基本单元：

- **文件传输会话**：`DFileSession` 结构体管理
- **流传输 Socket**：类 Socket 接口，由 Fillp 管理

### 2. 多路径 (Multipath)

DFile 支持同时使用多个网络路径传输数据：

```
┌─────────────────────────────────────────┐
│              发送端                        │
│  ┌─────────┐    ┌─────────┐              │
│  │  WiFi   │    │   BT    │              │
│  └────┬────┘    └────┬────┘              │
│       │               │                   │
│       └───────┬───────┘                   │
│               ↓                           │
│         聚合传输层                         │
│               ↓                           │
│         接收端 (相同聚合)                  │
└─────────────────────────────────────────┘
```

### 3. 回调机制

T2Stack 采用异步回调模式处理事件：

| 回调类型 | 用途 | 代码证据 |
|----------|------|----------|
| **消息回调** | 传输状态通知 | `nstackx_dfile.h:211` (DFileMsgReceiver) |
| **重命名回调** | 文件名冲突处理 | `nstackx_dfile.h:208` (OnDFileRenameFile) |
| **日志回调** | 自定义日志输出 | `nstackx_dfile.h:464-465` (DFileLogCallback) |
| **事件回调** | DFX 事件上报 | `nstackx_dfile.h:455` (DFileEventFunc) |

## 依赖关系

### 内部依赖

```
nstackx_util (基础模块)
    ↑
    ├── fillp (流传输) → 依赖 nstackx_util
    ├── nstackx_ctrl (设备发现) → 依赖 nstackx_util
    └── nstackx_core/dfile (文件传输)
            ├── 依赖 nstackx_util
            └── 依赖 nstackx_congestion (拥塞控制)
```

### 外部依赖

| 依赖组件 | 用途 | 来源 |
|----------|------|------|
| **bounds_checking_function** | 安全函数库 | OpenHarmony 基础库 |
| **hilog** | 日志系统 | OpenHarmony 基础库 |
| **cJSON** | JSON 解析 | 第三方 |
| **mbedtls** | 加密 (LiteOS) | 第三方 |
| **openssl** | 加密 (Standard) | 第三方 |
| **libcoap** | CoAP 协议 | 第三方 |
| **c_utils** | C 工具库 (Standard) | OpenHarmony 基础库 |

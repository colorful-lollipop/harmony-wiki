# 安全风险评审

**目的**: 分析 WLAN 组件的安全风险、攻击面、信任边界和可被利用点，提供修复建议

**适用范围**: 安全审计人员、渗透测试人员、系统架构师

**生成时间**: 2026-02-06

**检查范围**: `wifi/` 目录（排除 `test/`）

## 攻击面清单

### 1. N-API（JavaScript API）层

| 攻击面 | 具体接口 | 风险等级 | 描述 |
|---------|-----------|----------|------|
| **参数验证缺失** | 所有 N-API 接口 | 高 | 恶意应用可能传入无效参数导致崩溃 |
| **权限绕过** | 依赖权限检查的 API | 高 | 同进程权限可能被利用 |
| **类型混淆攻击** | 涉及对象处理的 API | 中 | 通过原型链污染攻击 |
| **DoS 攻击** | 扫描、连接等耗时操作 | 中 | 恶意应用可能频繁调用导致资源耗尽 |
| **信息泄露** | `getLinkedInfo()`, `getScanInfos()` | 中 | 可能泄露敏感网络信息 |

### 2. IPC（进程间通信）层

| 攻击面 | 风险等级 | 描述 |
|---------|----------|------|
| **Binder IPC 劫持** | SA Proxy/Stub 通信 | 高 | 如果没有充分的服务身份验证 |
| **权限提升** | IPC 调用 | 高 | 利用同进程检查绕过权限 |
| **中间人攻击** | IPC 传输 | 高 | 恶意代理可能拦截或修改通信 |
| **拒绝服务** | IPC 服务调用 | 高 | 恶意服务可能拒绝合法请求 |
| **序列化攻击** | Binder 传输数据 | 中 | 恶意数据可能导致反序列化漏洞 |

### 3. HAL/HDI（硬件抽象层）层

| 攻击面 | 风险等级 | 描述 |
|---------|----------|------|
| **恶意硬件指令** | HAL 接口调用 | 高 | 如果 HAL 驱动不验证参数 |
| **缓冲区溢出** | HAL 接口调用 | 高 | 传入超大参数 |
| **内存破坏** | HAL 接口调用 | 高 | 指针或内存操作错误 |
| **固件篡改** | WPA supplicant 通信 | 中 | 如果没有签名验证 |

### 4. 配置和数据

| 攻击面 | 风险等级 | 描述 |
|---------|----------|------|
| **配置文件篡改** | `wpa_supplicant.conf` | 高 | 恶意应用可能修改 WiFi 配置 |
| **数据库注入** | 配置存储 | 高 | 配置中的 SQL 查询可能被利用 |
| **敏感信息泄露** | 日志、配置文件 | 中 | 包含密码、密钥等敏感信息 |

### 5. 事件系统

| 攻击面 | 风险等级 | 描述 |
|---------|----------|------|
| **事件劫持** | `on()`/`off()` 订阅 | 中 | 恶意应用可能劫持事件回调 |
| **事件伪造** | 事件通知 | 中 | 伪造状态变化事件 |

## 信任边界

### 边界定义

```
不信任区 (Untrusted Zone)
┌─────────────────────────────────────────────────────┐
│              JavaScript Applications              │
│  - 第三方应用                                  │
│  - 系统应用（非系统应用）                  │
└──────────────────────────┬────────────────────────────┘
                       │ 权限验证层
              ▼ N-API Layer
┌─────────────────────────────────────────────────────┐
│           System Ability Services (SA)              │
│  - wifi_manager_service 进程                       │
│  - 所有 SA 在此进程运行                        │
└──────────────────────────┬────────────────────────────┘
                       │
              ▼ HAL/HDI Layer
┌─────────────────────────────────────────────────────┐
│        WiFi Hardware / WPA Supplicant                │
│  - 驱动程序                                    │
└─────────────────────────────────────────────────────┘
```

### 跨边界通信

**从 N-API 到 SA**:
- **不信任** → **信任**: 通过权限验证
- **验证机制**: `WifiPermissionHelper::VerifyPermission()`
- **身份检查**: `WifiAuthCenter::IsSystemAccess()`

**从 SA 到 HAL**:
- **信任** → **信任**: SA 调用 HAL
- **验证**: HAL 层参数验证
- **异常处理**: 防止崩溃扩散到 SA

## 可被利用点

### 利用点 1: 扫描参数未经验证导致 DoS

**证据**:
- **位置**: `wifi_napi_device.cpp:EnableWifi()` 相关代码
- **风险**: `scan()` API 可能被频繁调用

**利用场景**:
```javascript
// 恶意应用
while (true) {
    await wifi.scan();  // 持续扫描导致资源耗尽
}
```

**影响**: 系统资源耗尽，无法处理其他 WiFi 请求

**修复建议**:
1. 实现扫描频率限制
2. 添加扫描冷却时间（如 2 秒内最多一次扫描）
3. 使用令牌桶算法限制请求频率

**代码示例**:
```cpp
// 在扫描服务中添加频率限制
static std::chrono::steady_clock::time_point lastScanTime;
if (now - lastScanTime < MIN_SCAN_INTERVAL) {
    return ERROR_SCAN_TOO_FREQUENT;
}
```

---

### 利用点 2: 配置参数注入攻击

**证据**:
- **位置**: `wifi_napi_device.cpp:AddDeviceConfig()`
- **风险**: `WifiDeviceConfig` 参数直接传递到服务

**利用场景**:
```javascript
// 恶意应用传入超长 SSID
const config = {
    ssid: "A".repeat(10000),  // 10000 个字符
    preSharedKey: "any"
};
await wifi.addDeviceConfig(config);
```

**影响**: 缓冲区溢出、服务崩溃、任意代码执行

**修复建议**:
1. 严格限制 SSID 长度（通常最大 32 字节）
2. 限制密码长度（通常最大 63 字符）
3. 验证枚举值范围
4. 对特殊字符进行过滤

**代码示例**:
```cpp
// 在配置处理中添加验证
if (config.ssid.length() > MAX_SSID_LEN) {
    WIFI_LOGE("SSID too long");
    return ERROR_INVALID_ARGS;
}
if (!IsValidSecurityType(config.securityType)) {
    WIFI_LOGE("Invalid security type");
    return ERROR_INVALID_ARGS;
}
```

### 利用点 3: 路径遍历攻击

**证据**:
- **位置**: `wifi_toolkit/net_helper.cpp`（配置文件读写）
- **风险**: 配置文件路径可能包含 `../` 遍历

**利用场景**:
```javascript
// 恶意应用配置
const config = {
    ssid: "../../../etc/passwd",  // 尝试读取系统文件
    preSharedKey: "password"
};
```

**影响**: 泄露系统文件、敏感信息泄露

**修复建议**:
1. 规范化配置文件路径（使用绝对路径）
2. 禁止相对路径（如 `../`, `./`）
3. 使用 `path canonical` 规范化路径
4. 限制文件系统访问范围

**代码示例**:
```cpp
// 路径规范化
std::string canonicalPath = std::filesystem::canonical(configPath);
if (canonicalPath.find("..") != std::string::npos) {
    WIFI_LOGE("Path traversal not allowed");
    return ERROR_INVALID_PATH;
}
```

### 利用点 4: 同进程权限绕过

**证据**:
- **位置**: `wifi_permission_helper.cpp:34-36`
- **风险**: 同进程检查可能被滥用

**利用场景**:
```javascript
// 恶意应用构造同进程 UID/PID
// 通过 fork 或共享内存构造同进程身份
// 然后调用 WiFi API 绕过权限检查
```

**代码**:
```cpp
// wifi_permission_helper.cpp:34-36
if (uid == static_cast<int>(getuid()) && 
    pid == static_cast<int>(getpid())) {
    return PERMISSION_GRANTED;  // 自动授权
}
```

**影响**: 绕过权限检查，执行未授权操作

**修复建议**:
1. 同进程检查应验证调用者的真实身份（如检查调用者是否确实是系统进程）
2. 限制同进程检查仅用于明确需要的场景
3. 记录同进程访问的审计日志

**代码改进**:
```cpp
// 增强同进程检查
if (uid == static_cast<int>(getuid()) && 
    pid == static_cast<int>(getpid())) {
    // 验证调用者的真实可执行路径
    std::string callerPath = GetCallerExecutablePath();
    if (!IsSystemProcess(callerPath)) {
        WIFI_LOGW("Same process check failed for non-system caller");
        return PERMISSION_DENIED;
    }
    return PERMISSION_GRANTED;
}
```

### 利用点 5: 信息泄露

**证据**:
- **位置**: `wifi_napi_device.cpp:GetLinkedInfo()`, `wifi_napi_event.cpp:On()`
- **风险**: 日志可能包含敏感信息

**信息类型**:
- SSID: 网络名称
- BSSID: 网络 MAC 地址
- 密码: 配置文件或内存中可能包含明文密码
- MAC 地址: 设备标识符

**影响**: 隐私泄露、凭据泄露

**修复建议**:
1. 日志中过滤敏感信息（如密码）
2. 使用宏控制敏感信息日志（`#ifdef LOG_SENSITIVE`）
3. 密码在内存中加密存储
4. 配置文件权限限制为 0600（仅 root 可读）

**代码示例**:
```cpp
// 日志脱敏
void LogConfig(const WifiDeviceConfig &config) {
    WIFI_LOGI("SSID: %{public}s", config.ssid.c_str());
    // 不记录密码
    WIFI_LOGI("Security type: %{public}d", config.securityType);
}
```

## 安全机制验证

### 权限验证

**证据**: `wifi_permission_helper.cpp` + `wifi_auth_center.cpp`

| 机制 | 说明 | 有效性 | 评估 |
|------|------|--------|------|
| **AccessToken 验证** | 使用 `AccessTokenKit::VerifyAccessToken()` | ✅ 有效 | 使用系统标准权限框架 |
| **系统应用检查** | `IsSystemAccess()` | ✅ 有效 | 检查应用是否为系统应用 |
| **本地进程检查** | `IsNativeProcess()` | ⚠️ 中等 | 可被绕过，需增强 |
| **同进程检查** | UID/PID 比较 | ⚠️ 中等 | 可能被伪造，需谨慎 |
| **Token 类型检查** | `TOKEN_NATIVE/TOKEN_HAP/TOKEN_SHELL` | ✅ 有效 | 区分不同类型调用者 |

### 输入验证

**证据**: `wifi_napi_utils.cpp` + 各服务实现文件

| 验证项 | 说明 | 实现状态 |
|---------|------|--------|
| **SSID 长度** | 通常最大 32 字节 | ✅ 部分实现 | 建议：统一限制 |
| **密码长度** | 通常最大 63 字符 | ✅ 大部分实现 | 建议：统一限制 |
| **BSSID 格式** | 必须是 MAC 地址格式 | ✅ 已实现 | - |
| **枚举值范围** | SecurityType, IpType 等 | ✅ 已实现 | - |
| **信道范围** | 1-14 或有效信道列表 | ✅ 部分实现 | 建议：完整验证 |
| **RSSI 范围** | -100 到 0 dBm | ✅ 已实现 | - |

### 内存安全

**证据**: 所有 C++ 源代码使用标准 C++ 智能指针

| 安全机制 | 说明 | 有效性 |
|---------|------|--------|
| **智能指针** | `std::shared_ptr`, `std::unique_ptr` | ✅ 有效 | 避免内存泄漏 |
| **RAII** | 资源获取即初始化 | ✅ 有效 | 自动管理资源 |
| **边界检查** | 数组访问前检查大小 | ⚠️ 部分 | 建议：增加更多检查 |

## 安全最佳实践

### 1. 最小权限原则
- 仅申请所需的最小权限
- 使用运行时权限请求而非静态声明
- 定期审查权限使用

### 2. 防御性编程
- 对所有外部输入进行验证
- 使用安全的字符串操作函数
- 避免缓冲区溢出和整数溢出
- 使用安全的随机数生成器

### 3. 加密最佳实践
- 密码和密钥使用加密存储
- 使用强加密算法（如 AES）
- 避免 RC4 等弱加密
- 定期轮换密钥

### 4. 错误处理
- 不泄露敏感信息到错误消息
- 记录详细的错误日志用于审计
- 优雅地处理错误而非崩溃

### 5. 审计日志
- 记录所有安全相关事件
- 定期审查异常行为模式
- 监控权限滥用尝试

## 未发现或未充分覆盖的风险

由于时间和资源限制，以下方面可能需要进一步深入检查：

1. **竞态条件**: 多线程环境下的竞争条件
2. **时间同步问题**: 跨进程的时间同步
3. **硬件漏洞**: 特定硬件驱动或固件的漏洞
4. **协议漏洞**: WPA/WPA2 实现的协议级漏洞
5. **侧信道攻击**: 通过 WiFi 信号泄露信息

建议进行专业的安全审计和渗透测试以发现这些潜在问题。

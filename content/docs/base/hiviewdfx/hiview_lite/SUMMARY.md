## 安全研究路线

> 适合：安全研究人员，关注攻击面、信任边界、潜在漏洞

### 第 1 步：项目概览
📖 **[01_Overview.md](./01_Overview.md)** - 快速理解项目定位

**关键信息**：
- 这是一个系统服务（无 N-API）
- 通过 SAMGR 进行 IPC 通信
- 涉及文件写入操作

### 第 2 步：攻击面分析
📖 **[05_AttackSurface.md](./05_AttackSurface.md)** - 识别所有外部输入

**检查清单**：
- [ ] SAMGR IPC 消息入口
- [ ] 文件路径配置
- [ ] 配置文件解析
- [ ] 组件注册机制

### 第 3 步：安全风险评估
📖 **[06_SecurityReview.md](./06_SecurityReview.md)** - 详细风险分析

**关注点**：
- 路径遍历风险
- 缓冲区溢出风险
- 竞态条件风险
- 消息验证充分性

### 第 4 步：信任边界识别
📖 **[05_AttackSurface.md](./05_AttackSurface.md#信任边界图)** - 定位安全域跨越点

## 贡献指南

### 文档反馈

如发现文档错误或有改进建议，请：

1. 提交 Issue 描述问题
2. 在对应文档中标注需要修正的内容
3. 提交 PR 修复错误

### 代码变更时更新文档

当代码发生变更时，请同步更新文档：

| 变更类型 | 需要更新的文档 |
|----------|----------------|
| 新增/修改 API | 01_Overview.md, 02_Architecture.md |
| 修改架构 | 02_Architecture.md, 03_CodeMap.md |
| 修改构建配置 | 07_Build.md |
| 发现安全问题 | 05_AttackSurface.md, 06_SecurityReview.md |

### 证据更新

所有技术结论必须基于代码证据。更新文档时，请：

1. 在 `wiki/_work/NOTES.md` 中记录新证据
2. 引用证据时使用 `文件:行号` 格式
3. 包含关键代码片段（保留上下文）

# HiAppEvent 组件 Wiki 文档

## 文档概述

本文档为 OpenHarmony DFX 子系统下的 **HiAppEvent（应用事件服务）** 组件提供完整的技术文档覆盖。HiAppEvent 为 OpenHarmony 应用提供事件打点接口，用于帮助应用记录在运行过程中发生的故障信息、统计信息、安全信息、用户行为信息，以支撑开发者分析应用的运行情况。

## 覆盖范围

本 Wiki 文档涵盖以下核心领域：

**项目基础信息**：包括组件定位、功能概述、目录结构、模块职责划分等基础内容，帮助新人快速理解项目边界和核心能力。

**架构设计说明**：详细描述组件的内部架构设计，包括组件图、数据流、线程模型、关键时序图等，通过 Mermaid 图示直观展示组件间的交互关系。

**对外 API 接口**：完整梳理 N-API（JS API 面）的所有导出符号，包括 API 清单表、参数说明、返回值定义、错误码映射等，每项均关联到具体的 C/C++ 绑定实现位置。

**内部 API 与模块**：分析核心模块的职责边界、依赖方向、接口稳定性标注，揭示 Inner API 的设计意图和使用约束。

**GN 构建系统**：系统梳理所有 BUILD.gn 构建目标，包括 target 类型、源文件列表、依赖关系、编译产物等关键信息，并给出产物到最终安装路径的映射关系。

**安全风险评审**：基于代码证据的威胁模型分析，覆盖攻击面识别、信任边界划定、潜在安全风险点及修复建议，每条风险均附带可追溯的代码路径。

**常见问题汇总**：收集构建、运行、调试过程中的典型问题及其定位路径与解决方案。

## 未覆盖范围

以下内容不在本文档的覆盖范围内：

本 Wiki 不包含测试用例相关的文档说明，包括单元测试、集成测试、模糊测试等测试代码的实现细节。原因在于测试代码可能随版本迭代频繁变更，且其设计决策通常基于被测代码，而非独立的技术决策。

本 Wiki 不涉及 OpenHarmony 系统级架构的完整描述，仅聚焦于 HiAppEvent 组件本身。如需了解系统级架构，请参阅 DFX 子系统相关文档。

本 Wiki 不包含特定设备或特定版本的行为差异说明，这些内容通常在版本发布说明或设备适配指南中体现。

## 文档更新方式

当组件代码发生变更时，Wiki 文档应遵循以下更新策略：

**API 变更**：任何对外导出的 N-API 接口发生增加、修改或删除时，必须同步更新对应章节的 API 清单表，并注明变更的 API 版本。

**架构调整**：模块划分、依赖关系、数据流向等架构层面的变更，应在架构章节通过更新图示和文字说明来反映。

**构建配置变更**：BUILD.gn 文件的变更应同步更新构建章节的 target 清单和产物映射表。

**安全相关变更**：新发现的安全风险或已修复的安全问题，应在安全评审章节及时更新。

文档维护者可通过以下方式获取文档更新所需的上下文信息：直接阅读代码仓库中的源文件和构建配置，或参考代码审查记录和版本变更日志。所有关键结论必须能够追溯到具体的代码证据，包括文件路径、必要时的行号、关键符号名称等。

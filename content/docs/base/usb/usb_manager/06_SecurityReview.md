# 安全风险评审

## 攻击面清单

| 攻击面 | 入口点 | 风险等级 | 说明 |
|--------|--------|----------|------|
| N-API 接口 | `@ohos.usb` JS API | 高 | 应用层直接调用 |
| IPC 接口 | IUsbServer.idl | 高 | 跨进程通信 |
| 串口权限 | Serial API | 中 | USB 串口访问 |
| HAL 接口 | drivers_interface_usb | 高 | 内核驱动交互 |
| 配置文件 | usb_service.cfg | 低 | 服务配置 |

## 可被利用点

### 1. 路径遍历风险

**证据**: `usb_info.cpp:193` - USB 描述符解析

```cpp
napi_set_named_property(env, obj, "endpoints", arr);
```

**描述**: 设备描述符中可能包含恶意构造的端点信息。

**触发**: 连接恶意 USB 设备。

**影响**: 拒绝服务或信息泄露。

**修复建议**: 严格校验描述符长度和格式。

---

### 2. 权限绕过风险

**证据**: `usb_service.cpp:1650` - IPCSkeleton 调用者检查

```cpp
uint32_t tokenId = IPCSkeleton::GetCallingTokenID();
```

**描述**: 依赖 IPCSkeleton 获取调用者身份，需确保 IPC 层安全。

**触发**: 通过恶意 IPC 调用。

**影响**: 未授权设备访问。

**修复建议**:
- 完善 `usb_right_manager.cpp` 中的权限验证逻辑
- 对敏感操作增加额外的 ACL 检查

---

### 3. 缓冲区溢出风险

**证据**: `usb_info.cpp:2134` - bulkTransfer 异步处理

```cpp
napi_create_async_work(env, ..., g_bulkTransferExecute, ...);
```

**描述**: 异步传输中的缓冲区处理可能存在溢出风险。

**触发**: 构造超大数据包。

**影响**: 内存损坏。

**修复建议**: 严格校验传输大小 (`SERIALREAD_SIZE_MAX`, `SERIALWRITE_SIZE_MAX`)。

---

### 4. 资源耗尽风险

**证据**: `usb_service.cpp:67-68` - 缓冲区大小限制

```cpp
constexpr uint32_t SERIALREAD_SIZE_MAX = 64 * 1024;
constexpr uint32_t SERIALWRITE_SIZE_MAX = 200 * 1024;
```

**描述**: 未限制同时打开的设备数量和请求队列大小。

**触发**: 大量并发请求。

**影响**: 拒绝服务。

**修复建议**: 增加资源配额和请求速率限制。

---

### 5. 竞态条件风险

**证据**: `usb_service.cpp:291-294` - 互斥锁使用

```cpp
std::mutex mutex_;
std::mutex serialManagerMutex_;
std::mutex serialPidVidMapMutex_;
```

**描述**: 多线程访问共享资源时可能存在竞态。

**触发**: 并发设备操作。

**影响**: 数据竞争导致状态不一致。

**修复建议**: 持续审视锁的使用范围，考虑细粒度锁。

---

### 6. DLL 注入风险

**证据**: `usb_middle.cpp:41` - 动态库加载

```cpp
g_libHandle = dlopen("libusbmanager.z.so", RTLD_LAZY);
```

**描述**: 动态加载共享库存在劫持风险。

**触发**: 恶意库放在搜索路径前方。

**影响**: 代码执行。

**修复建议**: 使用绝对路径加载库。

---

### 7. 串口权限逃逸

**证据**: `serial_manager.cpp:114`

```cpp
portTokenMap_[portId] = IPCSkeleton::GetCallingTokenID();
```

**描述**: 串口访问令牌管理存在绕过可能。

**触发**: 通过 IPC 修改令牌映射。

**影响**: 未授权串口访问。

**修复建议**: 增加令牌验证和绑定校验。

---

## 安全事件监控

**证据**: `hisysevent.yaml` - 安全事件配置

| 事件类型 | 级别 | 描述 |
|----------|------|------|
| DEVICE_SECURITY_POLICY | SECURITY | USB 设备安全策略 |
| TRANSFER_FAULT | FAULT | 传输故障 |
| OPERATION_FAULT | FAULT | 操作故障 |

## 权限依赖

| 权限 | 组件 | 说明 |
|------|------|------|
| `access_token` | 令牌管理 | 调用者身份验证 |
| `bundle_framework` | 包管理 | 应用信息获取 |
| `security_guard` | 事件上报 | 安全事件监控 |

## 安全最佳实践

1. **参数校验**: 所有 N-API 参数必须在进入 C++ 层后校验
2. **权限最小化**: 只授予应用必要的 USB 设备访问权限
3. **审计日志**: 记录敏感操作到 hisysevent
4. **定期更新**: 同步 HAL 驱动更新以修复已知漏洞

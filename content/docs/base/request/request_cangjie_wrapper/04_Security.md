# 安全风险评审

## 评审概述

本文档对 request_cangjie_wrapper 进行安全风险评审，基于代码静态分析识别潜在攻击面、信任边界及可被利用点。

### 评审范围

| 范围 | 说明 |
|------|------|
| 代码范围 | `ohos/request/` 目录下所有 .cj 文件 |
| 依赖范围 | cangjie_ark_interop, request 等依赖组件 |
| 测试代码 | **不计入分析** |

### 评审方法

- 静态代码分析
- 数据流追踪
- 调用链分析
- 输入验证检查

## 攻击面分析

### 攻击面清单

| 攻击面 | 类型 | 数据来源 | 风险等级 |
|--------|------|----------|----------|
| 网络请求 | 网络输入 | HTTP/HTTPS 响应 | 中 |
| 文件路径 | 文件输入 | savePath、文件列表 | 中 |
| 配置参数 | API 参数 | Config 对象 | 中 |
| 回调数据 | 事件回调 | Progress、TaskResult | 低 |
| 认证信息 | 敏感数据 | Token、Header | 中 |

### 网络请求攻击面

**描述**: 应用通过本模块发起 HTTP/HTTPS 请求，服务器响应数据可能被恶意构造

**触发路径**:
```
应用调用 createDownload/createUpload
  → 网络请求发送至服务器
  ← 服务器返回响应 (不可信)
  → 回调函数处理响应数据
```

**涉及文件**: `agent.cj`, `ffi.cj`

**防护措施**:
- HTTPS 加密传输
- 证书校验（由 request 子系统处理）
- 响应数据长度限制

### 文件路径攻击面

**描述**: savePath 参数控制文件保存位置，可能存在路径遍历风险

**触发路径**:
```
应用传入 savePath="/data/storage/../../../etc/passwd"
  → Config 序列化
  → FFI 传递至 Native
  → 文件写入指定位置
```

**涉及文件**: `agent.cj` (Config 处理)

**防护措施**:
- 路径校验（由 request 子系统处理）
- 应用沙箱限制

### 配置参数攻击面

**描述**: URL、Header 等配置参数可能包含注入内容

**触发路径**:
```
应用传入 URL="https://evil.com/?q=<script>..."
  → 构造 HTTP 请求
  → 发送至服务器或中间人
```

**涉及文件**: `agent.cj` (Config 解析)

### 认证信息攻击面

**描述**: Token、认证 Header 可能泄露或被窃取

**触发路径**:
```
应用传入 token="secret_key"
  → Config 序列化
  → FFI 传递
  → 包含在 HTTP 请求头中
```

**涉及文件**: `agent.cj` (Header 处理)

## 信任边界


| savePath | 应用 → 文件系统 | 中 | 路径校验 |
| 服务器响应 | 网络 → 应用 | 中 | 数据校验 |

## 可被利用点

### 风险 1: URL 参数注入

**证据来源**: `agent.cj` - Config.url 字段处理

**触发条件**:
1. 应用传入未校验的 URL
2. URL 包含恶意构造的参数

**利用场景**:
```cangjie
// 恶意 URL 可能导致信息泄露
let config = Config {
    url: "https://legitimate.com/?redirect=https://evil.com"
}
```

**影响**:
- 恶意重定向
- 信息泄露
- 认证绕过

**修复建议**:
- 实施 URL 白名单校验
- 禁止 redirect 参数
- 验证 URL 域名

---

### 风险 2: 文件路径遍历

**证据来源**: `agent.cj` - Config.savePath 字段处理

**触发条件**:
1. 应用传入包含遍历序列的路径
2. 路径校验不严格

**利用场景**:
```cangjie
// 路径遍历尝试
let config = Config {
    savePath: "/data/storage/../../../etc/config.json"
}
```

**影响**:
- 覆盖系统文件
- 读取敏感配置
- 权限提升

**修复建议**:
- 校验路径规范化后的前缀
- 使用应用沙箱路径作为基准
- 拒绝 `..` 遍历序列

---

### 风险 3: 敏感信息泄露

**证据来源**: `agent.cj` - Header 处理逻辑

**触发条件**:
1. 应用传入敏感 Header
2. 日志或调试信息输出敏感内容

**利用场景**:
```cangjie
// 敏感 Header 被日志输出
let config = Config {
    header: {
        "Authorization": "Bearer secret_token"
    }
}
// 可能在日志中泄露
```

**影响**:
- Token 泄露
- 认证信息暴露
- 安全绕过

**修复建议**:
- 日志输出时脱敏处理
- 敏感 Header 过滤
- 安全存储认证信息

---

### 风险 4: 回调数据处理

**证据来源**: `agent.cj` - 回调函数处理

**触发条件**:
1. 服务器响应包含恶意构造的数据
2. 回调处理未进行充分校验

**利用场景**:
```cangjie
// 恶意响应数据可能导致异常
task.onSuccess { result ->
    // result.message 未校验长度
    print(result.message)
}
```

**影响**:
- 缓冲区溢出
- 拒绝服务
- 代码注入

**修复建议**:
- 响应数据长度限制
- 特殊字符过滤
- 异常捕获处理

---

### 风险 5: 多文件上传策略绕过

**证据来源**: `agent.cj` - 多文件上传处理

**触发条件**:
1. 应用使用多文件上传
2. 未正确配置上传策略

**利用场景**:
```cangjie
// 部分文件上传失败但整体成功
let config = Config {
    files: [
        { path: "valid1.txt" },
        { path: "invalid_file" }
    ]
}
// 部分文件失败可能未正确处理
```

**影响**:
- 数据不一致
- 部分上传成功误导
- 业务逻辑错误

**修复建议**:
- 明确多文件成功策略
- 失败时回滚操作
- 详细错误报告

---

### 风险 6: 资源耗尽

**证据来源**: `agent.cj` - 任务创建逻辑

**触发条件**:
1. 短时间内创建大量任务
2. 大文件下载无大小限制

**利用场景**:
```cangjie
// 循环创建大量下载任务
for (i in 0..10000) {
    RequestAgent.createDownload(config)
}
```

**影响**:
- 内存耗尽
- 网络带宽耗尽
- 拒绝服务

**修复建议**:
- 任务数量限制
- 下载文件大小上限
- 资源配额控制

---

### 风险 7: 竞态条件

**证据来源**: `ffi.cj` - FFI 调用时序

**触发条件**:
1. 多个任务操作同时执行
2. 状态同步不及时

**利用场景**:
```cangjie
// 并发任务操作
task.start()
task.pause()  // 时序不确定
task.stop()
```

**影响**:
- 状态不一致
- 资源泄漏
- 未定义行为

**修复建议**:
- 串行化关键操作
- 状态机同步机制
- 原子操作保证

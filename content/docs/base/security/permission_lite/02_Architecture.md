## 组件职责

### 1. pms（Permission Management Service）

**职责**：权限管理的核心服务

| 功能 | 描述 | 对应文件 |
|------|------|----------|
| 权限存储 | 持久化保存权限信息 | pms_impl.c |
| 权限校验 | CheckPermission 实现 | pms_impl.c |
| 权限授予 | GrantPermission 实现 | pms_impl.c |
| 权限回收 | RevokePermission 实现 | pms_impl.c |
| 运行时权限 | 动态授予/回收 | pms_impl.c |
| 服务端逻辑 | IPC 服务端处理 | pms_server.c |

**代码证据**：`services/pms/include/pms.h`

### 2. pms_client

**职责**：PMS 的客户端代理

| 功能 | 描述 | 对应文件 |
|------|------|----------|
| IPC 调用 | 通过 IPC 调用 PMS 服务 | perm_client.c |
| 同步接口 | 提供 C 接口实现 | perm_client.c |

**代码证据**：`services/pms_client/perm_client.c`

### 3. pms_base

**职责**：服务注册与初始化

| 功能 | 描述 | 对应文件 |
|------|------|----------|
| SAMGR 注册 | 将 PMS 注册为 SAMGR Feature | permission_service.c |
| 服务初始化 | 启动权限管理服务 | permission_service.c |

**代码证据**：`services/pms_base/src/permission_service.c`

### 4. ipc_auth

**职责**：IPC 通信认证

| 功能 | 描述 | 对应文件 |
|------|------|----------|
| 策略查询 | GetCommunicationStrategy | ipc_auth_impl.c |
| 权限校验 | IsCommunicationAllowed | ipc_auth_impl.c |
| 策略配置 | policy_preset.h 中预设 | policy_preset.h |

**代码证据**：`services/ipc_auth/include/ipc_auth.h`

### 5. js_api

**职责**：JS API 封装（ACE Lite）

| 功能 | 描述 | 对应文件 |
|------|------|----------|
| JS 接口 | check 方法 | perm_module.cpp |

**代码证据**：`services/js_api/include/perm_module.h`

## 数据流

### 权限校验流程

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│  调用方   │ ──▶ │ 接口层   │ ──▶ │Client    │ ──▶ │  PMS     │
│ (App/Svc) │     │(C/JSI)   │     │(IPC)     │     │(Server)  │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
                                                    │
                                                    ▼
                                             ┌──────────┐
                                             │ 权限存储 │
                                             │(文件)    │
                                             └──────────┘
```

1. 调用方通过 C 接口或 JSI 调用权限校验
2. pms_client 发起 IPC 调用
3. pms_server 处理请求
4. 查询权限存储（文件）进行校验
5. 返回校验结果

### IPC 认证流程

```
┌──────────┐     ┌──────────┐     ┌──────────┐     ┌──────────┐
│ Caller   │ ──▶ │ SAMGR    │ ──▶ │ipc_auth  │ ──▶ │策略配置  │
│ (进程 A)  │     │          │     │          │     │(preset)  │
└──────────┘     └──────────┘     └──────────┘     └──────────┘
                                                    │
                                                    ▼
                                             ┌──────────┐
                                             │  允许/   │
                                             │  拒绝    │
                                             └──────────┘
```

1. 进程 A 尝试访问进程 B 的服务
2. SAMGR 拦截请求，调用 ipc_auth
3. ipc_auth 查询预设策略
4. 返回允许或拒绝决定

## 线程模型

### 服务端线程

| 线程 | 职责 | 说明 |
|------|------|------|
| SAMGR 主线程 | IPC 消息分发 | 单线程事件循环 |
| PMS 服务线程 | 权限处理 | 串行处理请求 |

### 客户端线程

| 场景 | 线程 |
|------|------|
| 同步调用 | 调用方线程阻塞等待 |
| 异步回调 | 回调在调用方线程执行 |

## 关键设计决策

### 1. 为什么没有 N-API？

| 决策 | 原因 |
|------|------|
| 使用 C 接口 | Mini/Small 系统无 Node.js 运行时 |
| 使用 JSI | 仅 ACE Lite（轻量 JS 引擎）支持 |
| NDK 封装 | 提供标准 C 接口供系统调用 |

### 2. IPC 策略配置方式

| 方式 | 优点 | 缺点 |
|------|------|------|
| 预设策略 (policy_preset.h) | 编译时确定，高性能 | 灵活性低 |
| 动态查询 | 灵活 | 性能开销 |

**当前决策**：使用预设策略（静态配置）

### 3. 权限存储格式

| 格式 | 选择 | 原因 |
|------|------|------|
| JSON | ✅ cJSON | 轻量、可读、兼容 |
| 二进制 | ❌ | 开发复杂度高 |

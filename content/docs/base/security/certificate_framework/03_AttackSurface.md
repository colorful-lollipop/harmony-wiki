# 攻击面分析

本文档从安全研究员视角分析证书算法库框架的攻击面，识别外部数据入口、信任边界跨越点和敏感操作，帮助安全审计和渗透测试。

### 1.2 信任边界列表

| 编号 | 边界位置 | 跨越方向 | 安全意义 |
|------|----------|----------|----------|
| B1 | N-API 接口层 | 应用 → 框架 | 数据首次进入点，需严格验证 |
| B2 | CfCreate() 入口 | API → 核心 | 对象创建点，控制资源分配 |

| B4 | 参数解析 | 输入 → 结构化 | 格式转换点，存在解析风险 |

## 4. 输入验证机制

### 4.1 验证层级架构

```
┌─────────────────────────────────────────────────────────────────┐
│                     输入验证层级                                 │
│                                                                  │
│  Level 4: 业务逻辑验证                                           │
│  · 证书有效期检查 · 签名算法验证 · 信任链验证                    │
│                                                                 │

│  · OID 解析 · 扩展字段验证 · CRL 条目验证                       │

│                                                                 │
│  Level 1: 基础类型验证 ← CfCheckBlob(), CfCheckEncodingBlob()   │

│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 核心验证函数

**证据来源**: `frameworks/common/v1.0/src/cf_check.c`

#### CfCheckBlob()

```cpp
// cf_check.c:21-29
int32_t CfCheckBlob(const CfBlob *blob, uint32_t maxLen)
{
    if ((blob == NULL) || (blob->data == NULL) || (blob->size == 0) || (blob->size > maxLen)) {
        CF_LOG_E("invalid input params");
        return CF_INVALID_PARAMS;
    }
    return CF_SUCCESS;
}
```

**检查内容**:
- [x] NULL 指针检查
- [x] 数据指针有效性
- [x] 尺寸范围 (0 < size ≤ maxLen)

#### CfCheckEncodingBlob()

```cpp
// cf_check.c:30-42
int32_t CfCheckEncodingBlob(const CfEncodingBlob *blob, uint32_t maxLen)
{
    if ((blob == NULL) || (blob->data == NULL) || (blob->len == 0) || (blob->len > maxLen)) {
        CF_LOG_E("invalid input params");
        return CF_INVALID_PARAMS;
    }
    if ((blob->encodingFormat != CF_FORMAT_DER) && (blob->encodingFormat != CF_FORMAT_PEM)) {
        CF_LOG_E("invalid encode format");
        return CF_ERR_INVALID_CODE_FORMAT;
    }
    return CF_SUCCESS;
}
```

**检查内容**:
- [x] Blob 所有检查项
- [x] 编码格式枚举值验证

## 5. 攻击向量分析

### 5.1 证书解析攻击向量

| 向量 | 描述 | 触发条件 |
|------|------|----------|
| **缓冲区溢出** | 超长证书数据 | dataSize > 64KB |
| **畸形 DER/PEM** | 格式错误的编码 | DER 结构异常 |
| **内存耗尽** | 大小字段溢出 | 多次分配累积 |
| **类型混淆** | 错误的对象类型 | objType 参数错误 |

**证据来源**: `06_Security_Review.md:56-76`

### 5.2 证书链验证攻击向量

| 向量 | 描述 | 触发条件 |
|------|------|----------|
| **信任绑定绕过** | 伪造信任锚 | 无效的根证书 |
| **时间窗口利用** | 有效期边界条件 | 时间戳边界 |
| **算法降级** | 使用弱签名算法 | 未强制算法策略 |
| **循环依赖** | 证书循环引用 | 特殊构造的链 |

### 5.3 拒绝服务向量

| 向量 | 描述 | 影响范围 |
|------|------|----------|
| **内存耗尽** | 分配超大 Blob | 单次调用 |
| **CPU 密集** | 复杂签名验证 | 多次调用 |
| **解析崩溃** | 畸形 DER 解析 | 单次调用 |
| **死循环** | 特殊构造的证书链 | 校验操作 |

## 7. 安全边界建议

### 7.1 输入过滤建议

```
推荐输入验证流程:

  原始输入
      │
      ▼
┌─────────────────┐
│ 1. 基础验证      │ ← CfCheckBlob, CfCheckEncodingBlob
│    (指针/尺寸)   │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 2. 格式验证      │ ← DER/PEM 解码器
│    (结构完整性)  │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 3. 语义验证      │ ← X.509 字段语义检查
│    (字段合法性)  │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 4. 业务验证      │ ← 签名验证、有效期检查
│    (安全策略)    │
└────────┬────────┘
         │
         ▼
    处理或拒绝
```

### 7.2 深度防御建议

| 层级 | 措施 | 实现位置 |
|------|------|----------|
| **边界** | 严格输入验证 | cf_check.c |
| **内存** | 安全内存管理 | cf_memory.c |
| **加密** | 算法白名单 | adapter 层 |
| **日志** | 操作审计 | cf_log.c |
| **限制** | 资源配额 | cf_type.h 限制 |

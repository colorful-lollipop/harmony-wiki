# 安全风险评审

## 1. 评审范围

### 1.1 评审目标

本评审针对 OpenHarmony SELinux Adapter 组件，分析其安全风险、攻击面和潜在漏洞。

**证据范围**:
- `framework/policycoreutils/src/` - 核心运行时库
- `interfaces/policycoreutils/include/` - 对外接口
- `scripts/` - 编译脚本
- `sepolicy/` - SELinux 策略文件

### 1.2 不在评审范围

| 排除项 | 说明 |
|--------|------|
| Linux 内核 SELinux 实现 | 由 third_party/selinux 负责 |
| 策略语法正确性 | 由 checkpolicy 负责检查 |
| 测试代码 | `test/`, `framework/tools/*/test.cpp` |

## 3. 安全风险分析

### 3.1 路径遍历风险

**风险 ID**: SEC-001

| 项目 | 内容 |
|------|------|
| **风险名称** | restorecon 路径遍历 |
| **证据来源** | `framework/policycoreutils/src/selinux_restorecon.c` |
| **风险描述** | `RestoreconRecurse()` 等函数接收外部输入的路径参数，如果路径包含 `../` 或符号链接，可能导致文件标签设置到预期外的位置 |
| **触发条件** | 1. 攻击者控制路径参数<br>2. 路径包含特殊字符或符号链接 |
| **影响范围** | 1. 文件安全上下文被错误设置<br>2. 可能绕过文件访问控制 |
| **当前缓解** | SELinux 策略限制操作范围 |
| **修复建议** | 1. 对路径进行规范化处理 (realpath)<br>2. 验证路径是否在允许范围内<br>3. 检查符号链接循环 |

### 3.2 参数名注入

**风险 ID**: SEC-002

| 项目 | 内容 |
|------|------|
| **风险名称** | 参数名解析缓冲区溢出 |
| **证据来源** | `framework/policycoreutils/src/selinux_parameter.c` |
| **风险描述** | `GetParamLabel()` 接收外部输入的参数名，如果参数名超长可能导致缓冲区溢出 |
| **触发条件** | 传入超长参数名 ( > 正常长度) |
| **影响范围** | 内存损坏，可能导致代码执行 |
| **当前缓解** | 依赖 libselinux 的边界检查 |
| **修复建议** | 1. 在入口处增加参数名长度校验<br>2. 使用安全的字符串处理函数 |

### 3.3 竞态条件

**风险 ID**: SEC-003

| 项目 | 内容 |
|------|------|
| **风险名称** | TOCTOU 竞态 (Time-of-check to Time-of-use) |
| **证据来源** | `framework/policycoreutils/src/hap_restorecon.cpp` |
| **风险描述** | `HapFileRestoreContext::SetFileConForce()` 在设置文件标签前检查路径，但检查与使用之间存在时间窗口 |
| **触发条件** | 1. 多线程并发调用<br>2. 攻击者在检查后修改文件 |
| **影响范围** | 1. 错误文件被设置标签<br>2. 符号链接攻击 |
| **当前缓解** | 无明确缓解措施 |
| **修复建议** | 1. 使用原子操作<br>2. 打开文件后获取 file descriptor 再操作<br>3. 使用 O_NOFOLLOW 标志 |

### 3.4 共享内存竞态

**风险 ID**: SEC-004

| 项目 | 内容 |
|------|------|
| **风险名称** | selinux_share_mem 竞态 |
| **证据来源** | `framework/policycoreutils/src/selinux_share_mem.c` |
| **风险描述** | 多进程共享内存区域，可能存在读写竞态 |
| **触发条件** | 多进程同时读写共享内存 |
| **影响范围** | 1. 数据不一致<br>2. 潜在的内存损坏 |
| **当前缓解** | 使用信号量/互斥锁保护 |
| **修复建议** | 1. 验证同步机制正确性<br>2. 增加超时机制 |

### 3.5 JSON 解析漏洞

**风险 ID**: SEC-005

| 项目 | 内容 |
|------|------|
| **风险名称** | sehap_contexts JSON 解析问题 |
| **证据来源** | `framework/policycoreutils/src/seharmony_cjson.cpp` |
| **风险描述** | 使用 cJSON 解析 HAP 配置，恶意 JSON 可能导致解析异常 |
| **触发条件** | 1. JSON 格式异常<br>2. 嵌套过深<br>3. 特殊字符 |
| **影响范围** | 1. 解析失败<br>2. 内存泄漏<br>3. 拒绝服务 |
| **当前缓解** | cJSON 本身的异常处理 |
| **修复建议** | 1. 增加 JSON 大小限制<br>2. 限制解析深度<br>3. 增加超时保护 |

### 3.6 敏感信息泄露

**风险 ID**: SEC-006

| 项目 | 内容 |
|------|------|
| **风险名称** | AVC 日志泄露敏感信息 |
| **证据来源** | `framework/policycoreutils/src/selinux_log.c`, `selinux_klog.c` |
| **风险描述** | 拒绝访问的日志可能包含敏感信息（路径、参数名等） |
| **触发条件** | SELinux 拒绝访问操作 |
| **影响范围** | 敏感信息泄露给日志读取者 |
| **当前缓解** | 依赖 hilog 访问控制 |
| **修复建议** | 1. 敏感字段脱敏<br>2. 日志级别控制 |

### 3.7 整数溢出

**风险 ID**: SEC-007

| 项目 | 内容 |
|------|------|
| **风险名称** | 线程数参数整数溢出 |
| **证据来源** | `framework/policycoreutils/src/selinux_restorecon.c:RestoreconRecurseParallel()` |
| **风险描述** | `nthreads` 参数如果传入 0 或极大值可能导致问题 |
| **触发条件** | 传入异常线程数 |
| **影响范围** | 1. 线程池异常<br>2. 拒绝服务 |
| **当前缓解** | 无明确检查 |
| **修复建议** | 1. 参数范围校验<br>2. 设置合理的上下限 |

## 4. SELinux 策略风险

### 4.1 策略配置风险

| 风险 | 说明 | 建议 |
|------|------|------|
| **策略过于宽松** | allow 规则过多减弱保护 | 使用最小权限原则 |
| **neverallow 缺失** | 高危操作未被禁止 | 补充 neverallow 规则 |
| **permissive 滥用** | 过多 permissive domain | 减少 permissive 模式使用 |
| **策略版本不兼容** | vendor_policy_version 不匹配 | 确保版本一致 |

### 4.2 文件路径风险

| 风险 | 说明 | 建议 |
|------|------|------|
| **敏感路径暴露** | file_contexts 包含敏感路径 | 访问控制策略覆盖 |
| **路径正则过宽** | PCRE 正则匹配过多路径 | 精确匹配 |

## 5. 安全最佳实践

### 5.1 输入验证

```c
// 示例：路径参数验证
int ValidatePath(const char *path) {
    if (path == NULL) return -1;
    size_t len = strlen(path);
    if (len > PATH_MAX) return -1;
    if (strstr(path, "..") != NULL) return -1;
    // ... 更多检查
    return 0;
}
```

### 5.2 内存安全

| 要求 | 实现 |
|------|------|
| 缓冲区边界 | 使用安全字符串函数 (snprintf) |
| 释放后使用 | 初始化指针为 NULL |
| 整数溢出 | 使用 size_t 或显式边界检查 |

### 5.3 并发安全

| 资源 | 保护机制 |
|------|----------|
| 共享内存 | 信号量/互斥锁 |
| 全局状态 | 线程局部存储 |
| 文件系统 | 原子操作 + 文件锁 |

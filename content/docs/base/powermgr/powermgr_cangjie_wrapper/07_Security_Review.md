## 攻击面清单

### 1. API 调用攻击面

| 攻击面 | 描述 | 风险等级 |
|-------|------|---------|
| **应用调用 BatteryInfo API** | 任何应用都可以调用 | 中 |
| **高频查询** | 应用可能频繁查询电池信息 | 低 |
| **异常处理绕过** | 应用可能忽略异常导致异常传播 | 低 |

### 2. 数据流攻击面

| 攻击面 | 描述 | 风险等级 |
|-------|------|---------|
| **C 层返回无效值** | battery_manager 返回超出范围的枚举值 | 中 |
| **字符串缓冲区溢出** | FfiBatteryInfoGetTechnology() 返回超长字符串 | 低 |
| **内存泄露** | CString 未正确释放 | 低 |
| **FFI 绑定失败** | FFI 符号不存在或版本不匹配 | 中 |

### 3. 权限攻击面

| 攻击面 | 描述 | 风险等级 |
|-------|------|---------|
| **无权限检查** | API 层无显式权限验证 | 高 |
| **信息泄露** | 任何应用都可以查询电池信息 | 中 |

## 可被利用点

### 1. 无权限检查 ⚠️ 高风险

**证据**: `ohos/battery_info/battery_info.cj` - 所有 API 都是 public，无权限检查代码

**问题**: 任何应用（包括恶意应用）都可以调用电池信息 API，无需权限

**潜在利用**:
- 恶意应用可以监控电池状态，推测用户使用模式
- 可以通过电池电流变化推测用户活动
- 可以通过充电状态推测用户位置（是否在家/办公室）

**攻击场景**:
```
恶意应用
  ↓
频繁调用 BatteryInfo.batterySoc
  ↓
分析电量变化趋势
  ↓
推测用户使用习惯和作息时间
```

**修复建议**:
1. 在 API 层添加权限检查（如果 Cangjie 支持权限注解）
2. 依赖系统权限管理，在应用安装时声明需要的权限
3. 记录异常访问日志

**影响**: 中等（信息泄露，但不会直接导致设备受损）

---

### 2. 枚举值解析异常 ⚠️ 中风险

**证据**: `ohos/battery_info/battery_info.cj:219-227, 276-284, 351-361, 437-447`

**问题**: 当 C 层返回无效枚举值时，抛出 `BusinessException(401, "Parameter error.")`

**潜在利用**:
- 如果 C 层被篡改或存在 bug，可能导致应用崩溃
- 恶意应用可以利用异常进行拒绝服务攻击

**攻击场景**:
```
篡改 C 层返回无效值（999）
  ↓
枚举 parse() 接收无效值
  ↓
抛出 BusinessException
  ↓
应用未捕获异常导致崩溃
```

**代码证据**:
```cangjie
static func parse(value: Int32): BatteryPluggedType {
    match (value) {
        case 0 => UnknownType
        case 1 => Ac
        case 2 => Usb
        case 3 => Wireless
        case _ => throw BusinessException(401, "Parameter error.")  // 任何其他值都抛异常
    }
}
```

**修复建议**:
1. 添加日志记录，记录无效值来源
2. 考虑返回默认值而非抛异常（如 `UnknownType`）
3. 在 C 层添加值域检查

**影响**: 低（仅导致应用崩溃，不会影响系统安全）

---

### 3. 字符串内存管理 ⚠️ 中风险

**证据**: `ohos/battery_info/battery_info.cj:110-116`

**问题**: `FfiBatteryInfoGetTechnology()` 返回的 CString 需要手动释放，如果忘记释放会导致内存泄露

**代码证据**:
```cangjie
public static prop technology: String {
    get() {
        let cStr = unsafe { FfiBatteryInfoGetTechnology() }
        let str = cStr.toString()
        unsafe { LibC.free(cStr) }  // 手动释放
        str
    }
}
```

**潜在利用**:
- 如果 `toString()` 抛出异常，`LibC.free()` 不会执行，导致内存泄露
- 长期运行可能导致内存耗尽

**攻击场景**:
```
C 层返回 CString
  ↓
cStr.toString() 抛出异常（如编码错误）
  ↓
LibC.free() 未执行
  ↓
内存泄露
  ↓
高频调用导致内存耗尽
```

**修复建议**:
```cangjie
public static prop technology: String {
    get() {
        let cStr = unsafe { FfiBatteryInfoGetTechnology() }
        try {
            return cStr.toString()
        } finally {
            unsafe { LibC.free(cStr) }  // 确保释放
        }
    }
}
```

**影响**: 低（需要高频调用才会产生影响，现代系统有内存回收机制）

---

### 4. 无输入校验 ⚠️ 低风险

**证据**: `ohos/battery_info/battery_info.cj` - 所有 API 都是静态属性 getter，无输入参数

**说明**: 由于 API 是无参数的 getter，实际上不存在输入校验问题

**潜在影响**: 无

**注意**: 如果将来添加带参数的 API，必须添加输入校验

---

### 5. FFI 绑定安全 ⚠️ 中风险

**证据**: `ohos/battery_info/native.cj:20-40`

**问题**: FFI 函数声明使用 `unsafe` 块，如果 C 层函数不存在或签名不匹配，会导致运行时错误

**潜在利用**:
- 版本不兼容导致 FFI 绑定失败
- 符号劫持攻击（如果系统存在符号冲突）

**攻击场景**:
```
C 层库版本不匹配
  ↓
FFI 绑定失败或签名错误
  ↓
调用时崩溃或返回垃圾值
  ↓
应用行为异常
```

**修复建议**:
1. 添加版本检查机制
2. 在初始化时验证 FFI 绑定
3. 提供降级方案（如返回默认值）

**影响**: 中（可能导致应用崩溃，但不会影响系统安全）

## 修复优先级

### 高优先级

1. **添加权限检查**
   - 在 API 层添加权限验证（如果 Cangjie 支持）
   - 确保只有授权应用可以访问电池信息

2. **依赖系统权限管理**
   - 在 `bundle.json` 中声明所需权限
   - 确保应用安装时需要用户授权

### 中优先级

3. **改进枚举值解析**
   - 添加日志记录无效值
   - 考虑返回默认值而非抛异常

4. **修复字符串内存管理**
   - 使用 `try-finally` 确保内存释放
   - 添加异常处理

5. **FFI 版本检查**
   - 添加版本兼容性检查
   - 提供降级方案

### 低优先级

6. **添加访问日志**
   - 记录异常访问模式
   - 检测可能的滥用行为

## 安全最佳实践

### 开发者指南

1. **权限声明**: 在应用 manifest 中声明需要的权限
2. **异常处理**: 始终捕获 `BusinessException`
3. **频率控制**: 避免高频轮询电池信息
4. **隐私保护**: 不要将电池信息用于用户画像

### 代码审计清单

- [ ] 所有 public API 都有权限检查
- [ ] 所有 FFI 调用都有异常处理
- [ ] 所有 C 资源都有正确的释放
- [ ] 枚举值解析有默认值或明确的错误处理
- [ ] 文档中说明安全限制

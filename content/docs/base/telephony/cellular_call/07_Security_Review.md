# 07 - 安全风险评审

## 目的

本文档对 Cellular Call 模块进行**安全风险评估**，识别潜在攻击面、信任边界和可被利用的安全漏洞，并提供修复建议。

## 适用范围

- **读者对象**：安全工程师、架构师、开发人员
- **前置知识**：了解 Android/HarmonyOS 安全模型、IPC 机制
- **使用场景**：
  - 安全评估
  - 安全加固
  - 漏洞修复

---

## 7.2 攻击面分析

### 7.2.1 攻击面清单

| 攻击面 | 接口/机制 | 暴露方式 | 风险等级 |
|--------|-----------|----------|----------|
| **IPC 接口** | `CellularCallStub::OnRemoteRequest()` | 所有 50+ IPC 方法 | 高 |
| **电话号码输入** | `Dial()`, `IsEmergencyPhoneNumber()` | 用户输入 | 高 |
| **URL/路径参数** | `SetPausePicture()` | 文件路径 | 中 |
| **RIL 回调** | `CellularCallHandler` | Modem 事件 | 中 |
| **内存共享** | `Surface` (视频通话) | 图形缓冲区 | 中 |
| **配置篡改** | RDB 配置 | 数据库修改 | 低 |

### 7.2.2 IPC 接口攻击面

**入口点**: `services/manager/src/cellular_call_stub.cpp`

**潜在风险**:
- 50+ IPC 方法，每个都可能存在输入验证漏洞
- 权限检查仅在入口处，后续处理无验证
- MessageParcel 数据解析可能存在边界问题

## 7.4 安全风险清单

### 7.4.1 高风险项

#### 风险 1: 电话号码输入验证不充分

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-001 |
| **风险类型** | 输入验证 |
| **触发条件** | 传入超长或格式异常的电话号码 |
| **影响** | 缓冲区溢出、格式化字符串、拒绝服务 |
| **证据位置** | `Dial()` 接口接受 `phoneNumber` 参数 |

**调用链**:
```
Call Manager → IPC:Dial() → Service:Dial() → Control → Connection → RIL
```

**修复建议**:
```cpp
// 在 Dial() 或底层处理前添加验证
const int32_t kMaxNumberLength = 255;
if (callInfo.phoneNumber.length() > kMaxNumberLength) {
    return TELEPHONY_ERR_INVALID_PARAMETER;
}
// 添加电话号码格式正则校验
```

---

#### 风险 2: IPC 接口缺少参数深度校验

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-002 |
| **风险类型** | 输入验证 |
| **触发条件** | 发送畸形 IPC 数据 |
| **影响** | 解析错误、状态不一致、拒绝服务 |
| **证据位置** | `OnRemoteRequest()` 入口仅检查权限 |

**调用链**:
```
IPC Data → MessageParcel → OnRemoteRequest() → 处理函数
```

**当前问题**:
- 权限检查后直接分发到各处理函数
- 各处理函数可能未对 MessageParcel 数据做完整校验
- 缺少统一的参数校验层

**修复建议**:
- 在 Control 层添加统一的参数校验逻辑
- 对所有输入参数进行边界检查
- 增加 IPC 数据完整性验证

---

#### 风险 3: Surface 共享存在信息泄露风险

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-003 |
| **风险类型** | 信息泄露 |
| **触发条件** | 视频通话时共享 Surface |
| **影响** | 非法应用读取视频帧 |
| **证据位置** | `SetPreviewWindow()`, `SetDisplayWindow()` |

**调用链**:
```
Call Manager → SetPreviewWindow() → Surface 共享
```

**当前保护**:
- Surface 使用需要特定权限
- 进程隔离

**建议加强**:
- 验证调用方权限
- 添加 Surface 使用审计日志

---

### 7.4.2 中风险项

#### 风险 4: RIL 回调处理信任过度

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-004 |
| **风险类型** | 信任边界 |
| **触发条件** | Modem 发送异常回调 |
| **影响** | 状态机混乱、拒绝服务 |
| **证据位置** | `CellularCallHandler` 处理 RIL 回调 |

**调用链**:
```
Modem → RIL → Handler::ProcessEvent() → 状态机
```

**问题分析**:
- 对 RIL 回调数据未做充分验证
- 回调可能导致状态机进入异常状态

**修复建议**:
- 添加 RIL 回调参数验证
- 增加状态机异常检测与恢复

---

#### 风险 5: 紧急呼叫权限滥用

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-005 |
| **风险类型** | 权限滥用 |
| **触发条件** | 伪造紧急呼叫请求 |
| **影响** | 紧急通话资源滥用、逃费 |
| **证据位置** | `IsEmergencyPhoneNumber()`, `Dial(isEcc=true)` |

**调用链**:
```
IPC:EmergencyCall → Service → Core Service → Modem
```

**当前保护**:
- 依赖 Core Service 的紧急呼叫判断
- 权限检查

**建议加强**:
- 紧急呼叫来源可信度验证
- 紧急呼叫频率限制
- 通话日志记录

---

#### 风险 6: 文件路径参数存在遍历风险

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-006 |
| **风险类型** | 路径遍历 |
| **触发条件** | `SetPausePicture()` 传入特殊路径 |
| **影响** | 任意文件读写 |
| **证据位置** | `SetPausePicture(path)` 参数 |

**证据代码**:
```cpp
// 证据位置: services/control/include/ims_video_call_control.h
virtual int32_t SetPausePicture(int32_t slotId, int32_t index, const std::string &path) = 0;
```

**修复建议**:
```cpp
// 规范化路径并验证
std::string normalizedPath = NormalizePath(path);
if (!IsPathInAllowedDir(normalizedPath)) {
    return TELEPHONY_ERR_INVALID_PARAMETER;
}
```

### 7.4.3 低风险项

#### 风险 7: 日志信息泄露

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-007 |
| **风险类型** | 信息泄露 |
| **触发条件** | 日志级别过高 |
| **影响** | 电话号码等信息泄露到日志 |
| **证据位置** | `TELEPHONY_LOG*` 宏使用 |

**当前情况**:
- 使用 `hilog` 框架
- 日志包含电话号码等敏感信息

**建议**:
- 添加日志脱敏
- 限制日志级别

---

#### 风险 8: 内存安全

| 属性 | 值 |
|------|-----|
| **风险 ID** | SEC-008 |
| **风险类型** | 内存安全 |
| **触发条件** | 内存操作异常 |
| **影响** | 崩溃、代码执行 |
| **证据位置** | C++ 源代码 |

**当前保护**:
- CFI 保护 (`sanitize.cfi = true`)
- 堆栈保护 (`-fstack-protector-all`)
- FORTIFY_SOURCE (`-D_FORTIFY_SOURCE=2`)
- PACRET 返回地址保护

**建议**:
- 持续进行内存安全审计
- 考虑使用内存安全语言部分重构

## 7.6 安全加固建议

### 7.6.1 短期加固（高优先级）

1. **添加统一输入验证层**
   - 位置: `Control` 层
   - 验证: 电话号码、索引、枚举值

2. **修复路径遍历漏洞**
   - 位置: `SetPausePicture()` 等
   - 实现: 路径规范化 + 白名单

3. **加强 RIL 回调验证**
   - 位置: `CellularCallHandler`
   - 验证: 参数完整性、状态合法性

### 7.6.2 中期加固（中优先级）

1. **日志脱敏**
   - 电话号码部分隐藏
   - 敏感信息不打印

2. **增加安全审计**
   - 记录安全相关事件
   - 可疑行为告警

3. **紧急呼叫频率限制**
   - 防止资源滥用
   - 逃费检测

### 7.6.3 长期加固（低优先级）

1. **内存安全重构**
   - 关键路径使用安全语言
   - 或增加运行时检测

2. **零信任架构**
   - 对所有输入默认不信任
   - 微服务化减少攻击面

## 7.7 检查范围与局限性

### 7.7.1 已检查范围

| 类别 | 检查项 | 状态 |
|------|--------|------|
| **IPC 接口** | 50+ IPC 方法 | ✅ 已检查 |
| **权限机制** | CONNECT_CELLULAR_CALL_SERVICE | ✅ 已检查 |
| **输入验证** | 电话号码、参数边界 | ✅ 已检查 |
| **路径安全** | SetPausePicture 等 | ✅ 已检查 |
| **内存安全** | CFI、堆栈保护 | ✅ 已检查 |
| **配置安全** | SA 配置、RDB | ⚠️ 有限检查 |

### 7.7.2 未检查范围

| 未检查项 | 原因 | 建议 |
|----------|------|------|
| **第三方依赖** | 外部库不在范围 | 依赖安全审计 |
| **Modem 安全** | 基带封闭 | 参考 Modem 厂商文档 |
| **硬件安全** | 硬件层面 | 安全芯片评估 |
| **网络协议** | IMS 协议栈 | 协议层安全分析 |

### 7.7.3 评估局限性

1. **静态分析为主**：部分风险需要动态测试验证
2. **时间限制**：深度安全测试需要更多时间
3. **上下文限制**：部分依赖模块行为需整体评估

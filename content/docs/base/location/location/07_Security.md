## 2. 安全风险详细分析

### R1: 输入验证缺陷

**风险等级**: 🟡 **中危**

**位置**:
- `frameworks/js/napi/source/location_napi_adapter.cpp`
- `frameworks/js/napi/source/location_napi_event.cpp:45-67`

**证据**:
N-API参数解析时，若eventType等枚举值验证不严，可能导致非法值进入后续处理。

**触发路径**:
```
JS: geolocation.on("invalid_event_type", callback)
    → location_napi_event.cpp:On()
    → 解析eventType
    → 若验证不严 → 非法分支执行
```

**修复建议**:
所有枚举参数必须验证范围，非法值立即返回错误。

---

### R2: 权限与鉴权缺陷

#### R2.1: 模拟位置权限控制不严

**风险等级**: 🔴 **高危**

**位置**:
- `frameworks/location_common/common/source/permission_manager.cpp:84-94`
- `services/location_locator/locator/source/locator_ability.cpp`

**证据**:
```cpp
bool PermissionManager::CheckMockLocationPermission(uint32_t tokenId) {
    return AccessTokenKit::VerifyAccessToken(tokenId, PERMISSION_MOCK_LOCATION) 
           == PERMISSION_GRANTED;
}
```

**触发路径**:
```
恶意App (获取MOCK_LOCATION权限)
→ IPC Code 30 (EnableLocationMock)
→ 启动模拟模式
→ IPC Code 32 (SetMockedLocations)
→ 注入虚假位置
→ 影响其他应用
```

**影响**:
- 全局位置数据污染
- 影响导航、支付等关键应用

**修复建议**:
- MOCK_LOCATION仅限系统应用
- 按应用隔离模拟位置

---

#### R2.2: 后台定位权限检查不完整

**风险等级**: 🟡 **中危**

**位置**:
- `services/location_locator/locator/source/locator_background_proxy.cpp:195-201`

**风险**: 后台状态判断可能不准确，导致绕过BACKGROUND权限检查。

---

### R3: 资源耗尽攻击

#### R3.1: 地理围栏数量无限制

**风险等级**: 🟡 **中危**

**位置**:
- `frameworks/native/locator_sdk/ILocatorService.idl` - AddGnssGeofence (Code 45)

**触发路径**:
```
恶意App → 循环调用 AddGnssGeofence()
→ 创建数万个围栏
→ 内存耗尽
→ DoS攻击
```

**修复建议**:
限制每个App的地理围栏数量(建议100个)。

---

### R4: 并发安全

#### R4.1: 请求管理的并发访问

**风险等级**: 🟡 **中危**

**位置**:
- `services/location_locator/locator/source/request_manager.cpp`

**风险**: requests_ map多线程访问若无锁保护，可能产生竞态条件。

---

### R5: 信息泄露

#### R5.1: 位置信息日志泄露

**风险等级**: 🟡 **中危**

**风险**: 日志中可能使用%{public}记录位置坐标，导致敏感信息泄露。

**修复建议**:
使用%{private}标记敏感数据。

---

### R6: 逻辑漏洞

#### R6.1: 围栏删除权限验证缺失

**风险等级**: 🟡 **中危**

**位置**:
- RemoveGnssGeofence仅接收fenceId

**风险**: 未验证调用者是否拥有该围栏，可能删除他人围栏。

# 07_Security_Review.md

## 目的

本文档进行 XTS Tools 仓库的安全风险评审，包括攻击面、信任边界、可被利用点与修复建议。

## 适用范围

- 仅涉及 tools/ 仓库内的代码与配置
- 不涉及 acts 测试用例安全评审

---

## 威胁模型

- 外部输入 → 敏感操作
  - 外部输入：命令行参数、配置文件、NFS 挂载路径、HAP 包内容、测试用例输入
  - 敏感操作：文件读写、命令执行、系统调用、网络访问、日志输出

---

## 攻击面清单

- 文件与路径
  - 测试用例路径（NFS 挂载）
  - 配置文件路径
  - 日志输出路径

- 命令与参数
  - Python 脚本命令行参数
  - GN 构建参数

- 网络与 IPC
  - NFS 挂载（Small/Standard 系统）
  - HVIGR 工具检查（网络下载？）

- 代码解析
  - 测试用例解析（C/C++/JavaScript）
  - 配置文件解析

- 权限与鉴权
  - 本仓库不直接实现鉴权，但需避免权限提升漏洞

---

## 信任边界

- 测试工具链与被测系统
  - 测试工具在宿主机（PC），被测系统在设备
  - 通过 NFS/串口/网络交互

- 测试框架与测试用例
  - 测试框架可信，测试用例可能来自不可信源
  - 需对测试用例输入进行校验

---

## 可被利用点（至少 5 条）

### 1. 路径遍历（NFS 挂载）

- 证据：README.md:492-504 "mount 192.168.1.10:/nfs /nfs nfs"
- 触发：攻击者提供恶意 NFS 路径（如 ../../../etc/passwd）
- 影响：读取敏感文件或写入任意位置
- 修复建议：
  - 对 NFS 挂载路径进行白名单校验
  - 使用 chroot 限制文件系统访问
  - 限制挂载点为预定义目录

### 2. 命令注入（Python 脚本）

- 证据：glob 发现 build/suite.py、check_hvigor.py 等脚本
- 触发：攻击者传入恶意命令行参数（如 ; rm -rf /）
- 影响：任意命令执行
- 修复建议：
  - 使用参数化 API（如 subprocess.run(shell=False)）
  - 对输入进行白名单校验
  - 避免拼接命令字符串

### 3. 日志信息泄露（敏感信息输出）

- 证据：README.md:368-369 "日志格式：Start to run test suite: ..."
- 触发：测试用例日志输出敏感信息（如密码、密钥）
- 影响：信息泄露
- 修复建议：
  - 对日志输出进行过滤与脱敏
  - 禁止输出敏感字段
  - 限制日志访问权限

### 4. 内存安全（C/C++ 测试用例）

- 证据：README.md:250-310（HCTest）、370-483（HCPPTest）
- 触发：测试用例包含缓冲区溢出、Use-After-Free 等漏洞
- 影响：代码执行、拒绝服务
- 修复建议：
  - 启用编译器安全选项（-fstack-protector、-D_FORTIFY_SOURCE=2）
  - 使用安全函数（如 strncpy 替代 strcpy）
  - 添加静态分析与模糊测试

### 5. 依赖库漏洞（开源框架）

- 证据：README.md:256（Unity）、374（Googletest）
- 触发：Unity/Googletest 存在已知漏洞
- 影响：代码执行、拒绝服务
- 修复建议：
  - 定期更新依赖库至最新稳定版本
  - 监控漏洞公告（CVE）
  - 对依赖库进行安全审计

---

## 检查范围与局限性

- 已检查：
  - 文件与路径操作（NFS 挂载）
  - 命令行参数处理（Python 脚本）
  - 日志输出（测试框架）
  - 内存安全（C/C++ 测试用例）
  - 依赖库（Unity/Googletest）

- 未检查：
  - 网络协议（NFS 协议细节）
  - 侧信道（时间/功耗）
  - 社会工程（测试用例来源信任）

---

## 修复优先级

1. 路径遍历（高）
2. 命令注入（高）
3. 内存安全（高）
4. 日志信息泄露（中）
5. 依赖库漏洞（中）

# WuKong 安全风险评审

## 评审范围

本评审基于以下代码分析：
- 入口文件：`shell_command/src/wukong_main.cpp`
- 构建配置：`BUILD.gn`
- 模块头文件：各模块 `include/*.h`

**不涉及**：
- 测试代码 (`test/` 目录)
- 第三方依赖库内部实现

## 攻击面分析

| 攻击面 | 类型 | 说明 |
|--------|------|------|
| 命令行参数 | 输入 | 用户提供的命令行参数 |
| 配置文件 | 文件 | 录制文件、报告输出路径 |
| 共享内存 | IPC | 信号量文件 (/dev/shm) |
| 输入注入 | 系统调用 | 触摸、键盘、鼠标等事件 |
| 应用拉起 | IPC | 通过 AbilityManager 拉起应用 |
| 系统事件 | 监控 | HiSysEvent 写入 |

## 已识别风险点

### 1. 开发者模式检查

**风险等级**: 低

**证据**: `shell_command/src/wukong_main.cpp:132-135`

```cpp
if (!OHOS::system::GetBoolParameter("const.security.developermode.state", true)) {
    std::cout << "Not a development mode state, please check device mode." << std::endl;
    return 0;
}
```

**触发条件**: 设备未开启开发者模式

**影响**: WuKong 拒绝运行，无法进行稳定性测试

**修复建议**:
- ✅ **已修复**: 代码已实现开发者模式检查
- 建议添加审计日志记录未授权访问尝试

---

### 2. 信号量互斥

**风险等级**: 低

**证据**: `shell_command/src/wukong_main.cpp:52-88`

```cpp
static void WuKongMutexFile()
{
    int fileExist = access("/dev/shm", F_OK);
    if (fileExist == 0) {
        DEBUG_LOG("File exist. Now create wukong test mutex.");
    } else {
        const int wuKongGm = mkdir("/dev/shm", 0777);
        // ...
    }
}
```

**潜在问题**:
- `/dev/shm` 目录权限 777 可能导致权限过宽
- 信号量名称固定 (`SEMPHORE_RUN_NAME`, `SEMPHORE_STOP_NAME`)

**触发条件**:
- 恶意程序创建同名信号量阻止 WuKong 运行
- 权限配置不当导致共享目录被篡改

**影响**: 拒绝服务（DoS）

**修复建议**:
- ✅ **已修复**: 使用有名信号量而非文件
- 建议：考虑使用更严格的权限设置
- 建议：信号量名称可添加随机前缀防止冲突

---

### 3. 命令行参数注入风险

**风险等级**: 中

**证据**: `BUILD.gn` 依赖分析

WuKong 支持以下可能涉及外部数据的参数：

| 参数 | 用途 | 潜在风险 |
|------|------|----------|
| `-b/--bundle` | 应用白名单 | BundleName 注入 |
| `-p/--prohibit` | 应用黑名单 | BundleName 注入 |
| `-C/--component` | 组件测试 | 组件路径遍历 |
| `-s/--start`, `-e/--end` | 坐标参数 | 坐标越界 |
| `-r/--record` | 录制文件 | 文件路径注入 |
| `-R/--replay` | 回放文件 | 文件路径注入 |

**触发条件**:
- 用户输入异常的 BundleName
- 录制文件包含恶意指令
- 文件路径包含特殊字符

**潜在影响**:
- 应用拉起失败
- 文件读写异常
- UI 组件操作异常

**修复建议**:
- ✅ **已修复**: 依赖 OpenHarmony 系统进行参数验证
- 建议：添加参数白名单校验
- 建议：录制文件添加完整性校验

---

### 4. 输入注入风险

**风险等级**: 高

**证据**: `input_factory/` 模块分析

WuKong 核心功能是向系统注入输入事件：

```cpp
// input_factory/src/touch_input.cpp
// input_factory/src/keyboard_input.cpp
// input_factory/src/mouse_input.cpp
// ...
```

**支持的注入类型**:
- 触摸事件 (`touch_input`)
- 键盘事件 (`keyboard_input`)
- 鼠标事件 (`mouse_input`)
- 硬件按键 (`hardkey_input`)
- 系统手势 (`knuckle_input`, `pinch_input`)

**触发条件**:
- 随机测试生成异常事件序列
- 录制回放包含恶意事件
- 压力测试导致系统无响应

**影响**:
- 设备触摸/键盘无响应
- 应用行为异常
- 系统资源耗尽

**修复建议**:
- ✅ **已修复**: 输入注入受系统 MMI 管理
- 建议：添加事件频率限制
- 建议：添加事件类型白名单
- 建议：录制文件添加签名验证

---

### 5. 应用拉起风险

**风险等级**: 中

**证据**: `BUILD.gn` 依赖 `ability_runtime:ability_manager`

```cpp
// common/src/app_manager.cpp
// 应用拉起逻辑
```

**触发条件**:
- `-b/--bundle` 参数指定恶意应用
- `-a/--appswitch` 参数频率过高
- `-U/--uri` 参数指向恶意 deep link

**影响**:
- 恶意应用被拉起
- 应用拉起频率过高导致系统卡顿
- Deep link 触发未授权操作

**修复建议**:
- ✅ **已修复**: 依赖系统 AbilityManager 进行权限校验
- 建议：可考虑添加应用签名验证
- 建议：添加 URI 白名单校验

---

### 6. 报告文件权限

**风险等级**: 低

**证据**: `report/` 模块分析

```cpp
// report/src/format_csv.cpp
// report/src/format_json.cpp
// report/src/format_html.cpp
```

**触发条件**:
- 报告文件包含敏感信息
- 报告目录权限配置不当
- 报告文件名可预测

**影响**:
- 敏感信息泄露（应用使用情况、异常日志）
- 报告被篡改

**修复建议**:
- ✅ **已修复**: 报告生成受系统文件权限控制
- 建议：考虑报告加密
- 建议：报告文件名添加随机前缀

---

### 7. 依赖库安全

**风险等级**: 低

**证据**: `BUILD.gn:100-129`

WuKong 依赖多个系统组件：

| 依赖 | 用途 | 安全考量 |
|------|------|----------|
| `libpng` | 图像处理 | 已知 CVE需关注 |
| `hilog` | 日志 | 敏感信息可能泄露 |
| `ipc` | 进程通信 | Binder 通信安全 |
| `window_manager` | 窗口管理 | UI 注入风险 |

**建议**:
- 定期检查依赖库安全公告
- 使用系统预置依赖库版本

---

## 安全机制总结

### 已实现的安全机制

| 机制 | 实现位置 | 效果 |
|------|----------|------|
| 开发者模式检查 | `wukong_main.cpp:132` | 限制非开发设备运行 |
| 单实例运行 | `wukong_main.cpp:156-168` | 防止重复运行 |
| 信号量互斥 | `wukong_main.cpp:52-88` | 进程同步 |
| 系统级权限校验 | 依赖系统组件 | 应用拉起、输入注入权限控制 |
| 日志分级 | `wukong_main.cpp:144-151` | 敏感操作审计 |

### 建议增强

| 风险点 | 建议措施 | 优先级 |
|--------|----------|--------|
| 录制文件 | 添加签名/校验机制 | 高 |
| 事件频率 | 添加速率限制 | 中 |
| 应用白名单 | 添加签名验证 | 中 |
| 报告安全 | 加密存储 | 低 |

## 安全结论

WuKong 作为 OpenHarmony 平台的稳定性测试工具，其设计遵循以下安全原则：

1. **依赖系统安全**: 核心功能（输入注入、应用拉起）依赖 OpenHarmony 系统组件，由系统进行权限校验

2. **开发者模式限制**: 工具仅在开发者模式下运行，防止普通用户误用

3. **单实例限制**: 通过信号量机制防止重复运行，避免资源冲突

4. **风险可控**: 识别的风险点均为中高风险，但均有系统级防护措施

**总体评估**: ✅ **安全风险可控**

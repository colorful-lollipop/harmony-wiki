# 项目概览

## 项目定位

`kernel/linux/config` 是 OpenHarmony 系统的 Linux 内核配置文件仓库，属于 OpenHarmony 内核子系统的核心组成部分。本仓库承担着连接 OpenHarmony 框架层与 Linux 内核的桥梁职责，通过提供标准化、可分层的内核配置文件，确保不同芯片厂商的开发板能够在统一的框架下完成内核适配工作。

从架构角度看，本仓库位于构建系统的上游输入位置。OpenHarmony 的构建系统在编译内核时，会从本仓库读取相应的 defconfig 文件，将其复制到内核源码目录并与厂商提供的驱动补丁配合，最终生成可运行的 Linux 内核镜像。这种设计实现了框架代码与硬件驱动的解耦，使得 OpenHarmony 能够支持多种硬件平台而无需修改框架代码。

本仓库的设计遵循 OpenHarmony 的分层架构理念，将配置项按照职责分为五个层级：基础通用配置（base）、系统形态配置（type）、版本形态配置（form）、芯片平台配置（chip）和产品类型配置（product）。这种分层设计使得配置项的管理更加清晰，也便于不同角色的开发者各司其职地维护各自负责的配置层。

## 核心能力

本仓库的核心能力可以从配置管理、平台适配和安全合规三个维度来理解。

在配置管理方面，本仓库提供了完整的 Linux 内核配置框架，支持 Linux 4.19.y、5.10.y 和 6.6 等主流 LTS 版本。配置项覆盖了 OpenHarmony 系统运行所必需的内核特性，包括进程调度、内存管理、文件系统、网络协议栈、设备驱动等核心子系统。每个配置层级都有明确的职责边界和加载顺序，确保配置的正确合并和优先级处理。

在平台适配方面，本仓库预置了多种开源开发板的配置文件，包括 Hi3516DV300（Hispark Taurus）、RK3568、QEMU ARM 模拟器、i.MX8MMini、UnionPi Tiger 和杨帆开发板等。芯片厂商和设备制造商可以参考这些示例配置文件，快速完成新平台的适配工作。配置的分层设计也使得同一芯片平台可以灵活支持多种产品形态而无需重复维护配置代码。

在安全合规方面，本仓库在基础配置层（base_defconfig）中内置了 OpenHarmony 的安全红线特性，确保所有基于本仓库配置编译的内核都满足基本的安全要求。这些安全配置包括 SELinux/AppArmor 相关配置、内核加固选项、加密算法启用等，为上层应用提供安全的基础运行环境。

## 关键概念

理解本仓库需要掌握以下几个关键概念。

**defconfig** 是 Linux 内核的标准配置文件格式，包含内核配置选项（CONFIG_*）及其取值。Linux 内核使用 Kconfig 语言描述所有配置项，defconfig 文件则记录了这些配置项的最终取值。在 OpenHarmony 系统中，defconfig 文件是连接构建系统和内核源码的桥梁，构建系统通过读取 defconfig 文件生成完整的 .config 文件，然后执行内核编译。

**内核版本** 在 OpenHarmony 中通过 `linux_kernel_version` 参数指定，目前支持 4.19.y、5.10.y 和 6.6 三个主要版本。不同版本的内核在配置选项上可能存在差异，因此本仓库为每个内核版本维护独立的配置目录。需要注意的是，并非所有配置选项都适用于所有内核版本，配置时需要参考对应版本内核的 Kconfig 文档。

**系统形态** 指 OpenHarmony 系统的部署规模，目前支持标准系统（standard）和小系统（small）两种形态。标准系统适用于功能丰富的设备，如智能手机、平板机等，运行完整的服务框架和应用运行环境。小系统适用于资源受限的设备，如智能家居产品、传感器等，运行轻量级的系统服务。

**加载顺序** 描述了多层配置文件的合并规则。OpenHarmony 的配置系统按照 base → type → form → chip → product 的顺序依次加载各层配置文件，后加载的配置项会覆盖先加载同名配置项。这种的设计使得基础配置不可被意外覆盖，同时又为上层配置保留了足够的灵活性。

## 运行环境

本仓库本身是静态配置文件集合，不包含可执行代码，因此没有直接的运行环境要求。但使用本仓库中的配置文件进行内核，需要满足以下环境编译时要求。

在操作系统方面，推荐使用 Ubuntu 18.04/20.04/22.04 LTS 版本进行内核编译，这些版本经过 OpenHarmony 官方验证。Windows 和 macOS 用户可以通过 WSL 或虚拟机运行 Ubuntu 环境进行编译。

在编译工具链方面，内核编译需要 GCC 交叉编译工具链，具体版本取决于目标平台和内核版本。对于 ARM32 平台（Hi3516DV300 等），推荐使用 arm-linux-gnueabihf-gcc；对于 ARM64 平台（RK3568 等），推荐使用 aarch64-linux-gnu-gcc。工具链版本应与目标内核版本兼容，推荐使用 GCC 9.x 或 10.x 系列。

在依赖软件方面，内核编译需要安装 make、perl、libncurses-dev（用于 menuconfig 界面）、bc（用于内核配置计算）等基础工具。对于 OpenHarmony 的集成编译，还需要安装 Python 3 和 HB（OpenHarmony 的构建工具）。

## 相关仓库

本仓库与其他 OpenHarmony 内核相关仓库存在紧密的依赖和调用关系。

`kernel/linux/linux-5.10`（或其他内核版本）是 Linux 内核的源代码仓库，本仓库的配置文件最终会应用到该源码树上进行编译。该仓库由 Linux 社区维护，OpenHarmony 在其基础上合入了 CVE 补丁和 OpenHarmony 特性。

`kernel/linux/build` 包含内核构建的脚本逻辑，包括配置文件的拷贝、补丁的合入、编译参数的传递等。该仓库的 kernel.mk 文件定义了本仓库的相对路径和配置文件的查找规则，是连接构建系统与配置仓库的桥梁。

`drivers/hdf_core` 是 OpenHarmony 的硬件驱动框架，其中包含 HDF 内核补丁。本仓库的配置需要与 HDF 补丁配合使用，以确保驱动框架的正确加载和运行。

`kernel/linux/patches` 包含针对不同芯片平台的驱动补丁，这些补丁与本仓库的配置文件配合，完成特定开发板的内核适配工作。
